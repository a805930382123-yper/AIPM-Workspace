# RAWOCR02 图片精读、草稿与检索证据

用户已授权第二轮。基线 `f2962bb41e5c16b3aecde8c751f3f2c155662e3f`，依照原规格第 4 节及已通过的 RAWOCR01 数据契约。需求明确度 1（需适配现有模型及证据协议）、耦合 2（Provider、Raw、草稿、检索）、风险 2（原文和引用完整性）、本链既往失败 0，合计 5，采用 B 模式。Astra medium 负责规划与独立验收，Sol High 负责产品、定向测试与施工报告，主 Agent 管理状态、全量检查和同步。

## 施工与验收条件

1. **单图与批量 API。** 按 Raw ID 和出现位置 mediaId 读取本地校验过的原图。单图支持显式重试失败项及 force 重读；批量支持待解析项或明确选择的图片，按图返回结果。在同篇至少 5 张待解析图上观测在途请求不超过 3，一张失败时其余完成，已解析项普通重复调用不重复付费。图片读取或文档检索本身不发起 VLM 调用。
2. **Provider 请求。** 复用已有图片与结构化调用边界。以本地 JPEG 等非 PNG 原图测试预处理，长边超过 2048 时等比缩至 1536–2048；保留原图字节。发送标题及图标记前后各最多 250 字可用正文，排除调试 OCR 和旧内嵌转录。依规格保留可见信息、术语、模糊警告与分类排版约束。支持的模型使用严格 JSON Schema、温度 0.1、输出上限 1536 token、有限超时；对协议不兼容的参数按实际能力调整并记录。原生 schema 不可用时采用 json_object 与同等本地校验，既有知识与 PDF 请求保持兼容。
3. **响应与失败。** 严格检查规格六个必填字段、枚举、类型和额外字段；摘要清除换行并限制 40 字，剥离 Markdown 外围围栏，保留内部格式。skip、decorative 或清洗后空正文均清空展示文本；成功记录模型、时间、类型、摘要、正文、置信度、警告。定向模拟瞬时故障与非法 JSON，各类最多重试一次，日志可核对次数，持续失败落 failed 及脱敏错误。用模拟 Provider 核对实际请求体及落盘重读，付费调用预算为零。
4. **草稿及真实检索链路。** 正常生成知识草稿时先以并发上限 3 补全 needs_vlm，再按图序消费 ocr_ready 的清洗文本和 vlm_done 的摘要/正文。用每种状态不同的哨兵实测，skipped、failed、needs_vlm 的原始 OCR 不进入任何 Prompt、检索上下文或结果；单图失败时正文仍能产出草稿。复用同一组装规则接到知识问答实际 Raw 补读路径（`services/llm/knowledge-answers.ts` 的 needsRaw/query → rawFragments），用只有图片中出现的词验证检索、消费与溯源。现有 Raw 列表只过滤标题、来源和标签，本轮不新增全文搜索产品。
5. **证据与续跑。** 保持原正文 UTF-8 字节、bodySha256、修订号及原引文 UTF-16 [start,end) 一致。用同一文档“图前正文、图中文字、图后正文”检验正文引文仍切回原文，图片引文单独指向具体 Raw、图片位置及对应解析文本，拒绝从正文定位器伪造图文引用。走真实草稿生成、检查点续跑及用户确认路径：原图文证据仍匹配时可确认，引用的解析内容变更时须能发现失效；兼容无图片、旧检查点及原有正文证据。归档前先核验，不自动写正式 Wiki/Prompt。

## 边界与交接

测试通过 RAWOCR01 内部存储建立隔离样本。第三轮负责新导入和详情页交互，第四轮负责历史数据迁移。施工者自查后交接改动、命令、结果与 SHA 并停写；验收者独立实测 API、草稿/检索/续跑和证据确认，分别裁决本轮缺陷与批次整体。主 Agent 在隔离环境运行项目门禁并核对同步状态，按轮汇报后停止。
