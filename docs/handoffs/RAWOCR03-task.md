用户已授权第三轮，基线 `2ca4c9f`。本卡在施工前冻结；第四轮历史迁移不在本次授权范围。

## 来源、范围与评分

范围依据 [RAWOCR01](RAWOCR01-task.md) 第 4 项、[RAWOCR02](RAWOCR02-task.md)「边界与交接」及本次第三轮授权。前两卡提及的独立“原规格第 3/4 节”在仓库未定位，当前会话也无补充原文；不得声称已核对其完整视觉细节。本卡从已通过的数据/API 契约与现行导入、阅读行为确定可验证交付，不新增第四轮能力。[产品规格第六章](../product-spec.md#六raw-原始资料) 的 Raw 保真原则继续有效。

基线中 `services/raw/web-material.ts` 仍将原始 OCR 内嵌正文，仅资讯候选导入调用它；`server/raw-import.ts` 的手工网页导入仍只取文字。详情页 `app/pages/RawPage.tsx` 只展示原图和正文，尚未消费单图派生产物。本轮统一这两个网页导入入口的图片分流，并接通已有精读接口。

Agent Router 评分：需求明确度 **1**（原规格正文缺口，以本卡冻结交互）；模块耦合 **2**（网页获取、Raw 持久化、资讯入库及详情 UI）；变更风险 **2**（原文及来源位置完整性）；历史失败 **0**（新导入与交互未施工，前轮缺陷已关闭）。合计 **5，B 模式**。规划与独立验收由 Astra medium，施工由 Sol High；真实模型及实例由主 Agent 的实际创建记录确认。施工者和最终验收者必须不同实例。

## 接口、所有权与排除项

复用 `RawStore` 单图派生存储、`identifyWebImages`、`evaluateImageOcr` 和 `/api/raw/:rawId/media` 下已有读/精读接口。允许为新导入贯通必要的输入和 API 类型；调试 OCR 只留内部派生存储，不能随 Raw 公共对象泄露。新导入持久化须在 Raw ID 确定后绑定出现位置，不引入第二套状态或阈值。

施工者负责 `services/raw/` 的导入相关模块、`services/news/raw-material.ts` / `raw-save.ts`、`server/raw-import.ts` 与必要接线、详情页及其局部组件/样式、相关测试和 `docs/reports/RAWOCR03-builder.md`。共享工作区，不覆盖其他人修改；改变上述范围外接口须先向主 Agent说明必要性。规划者仅写本任务卡；独立验收者写验收报告及独立验收脚本；主 Agent 管理状态、验收台账及 Git。

不做历史批量迁移、自动回填旧 Raw、阈值重新设计、新 VLM Provider、全文搜索、文件上传图片新产品或整体 Raw 页重构。不改正式 Wiki/Prompt；不新增真实付费模型预算（**0**）。新增 UI 遵循现有 Raw 页面风格，使用已有组件与交互约定。

## 检查、交接与停止

按 [testing.md](../testing.md) 使用独立系统临时目录、空模型配置与随机端口，禁止接触正式数据或运行中用户服务。施工者运行新增定向测试、RAWOCR01/02 和受影响导入/UI 回归，交接实际命令、结果、变更文件与 SHA 后停写。主 Agent 完成隔离 `npm run check`；独立验收须对实际版本执行关键导入与浏览器操作，允许复用同版本未受影响回归并明确注明。证据按 [evidence-policy.md](../evidence-policy.md) 收敛。

报告分别裁决「本轮施工范围内缺陷」和「RAWOCR03 整批」，附实际提交或基线加文件 SHA；缺失必选实测不能 PASS。范围内问题回交施工者修复后复验。全部必选项通过后主 Agent 更新状态、按既有授权提交同步并汇报；停止，不自动启动 RAWOCR04。
