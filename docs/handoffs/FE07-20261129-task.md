## 冻结拆分边界

原路径仅保留原有 `AutomationPage` 运行时公开导出，全部 props、可选性和回调参数保持兼容。页面继续拥有深链、Tab/收件箱导航、筛选与选择、焦点联动、编辑器和所有写动作。

| 模块（允许同义命名） | 职责 |
|---|---|
| `automation/useAutomationPolling.ts` | 搬迁原 8 个读取 effect、poll helper 及紧密关联的读取 state/error；以页面条件与 revision 为输入，返回页面需要的读取结果及写动作使用的原更新接口。 |
| `automation/AutomationSummaryBar.tsx` | 原状态 banner 完整 JSX、展示派生值及受控回调；页面保留暂停确认状态与实际写请求，不在组件重复存储状态。 |
| `AutomationPage.tsx` | 保持深链 effect、Tab 和抽屉组合、焦点 effect、写动作及其版本/锁/回调顺序。 |

8 个读取 effect 是：状态与计划（同一 effect 内 allSettled）、健康度、提醒、候选、流水线设置、周报、运行列表、运行详情。流水线设置为依赖变化时单次读取，其余为原 3000ms 完成后递归轮询。不得改成 setInterval、合并各读取时钟、按 Tab 隐藏停止读取，或引入通用状态框架。

允许移动紧密关联的内部职责以满足尺寸，但不可借此扩大到写动作重构；单用逻辑留所属模块，不为每字段拆文件。每份新增/修改产品文件须同时 **<40,960 B、<800 行**，正常格式化，入口显著缩小；运行时依赖是 DAG，子模块不得反向导入页面门面，类型依赖用 import type。全仓及页面加迁移模块告警总数均不得高于拆前实测基线。

## 等价行为

逐 effect、函数、JSX 对照基线，检查初始化、依赖数组、cleanup、闭包、调用次序、DOM/class/文案和错误区域，解释所有非机械差异。

- 保留各读取 effect 原依赖：refresh、各 revision、showHealth/showReminders、hasPipeline/hasWeeklyReview、candidateDate、运行筛选/limit、selectedRunId；条件关闭不擅自清空旧值。
- 每个 poll 在自身请求完成后才安排下一次；cleanup abort 并清 timer，所有读响应按原 signal.aborted 判断后更新；各 poll 可相互并行。“无并发”指同一未撤销轮询生命周期内无重叠，不承诺旧请求物理终止后才启动新条件请求。
- 状态/计划 allSettled 独立成功、失败与清错；其他错误保留已有值并按原分支恢复；流水线设置依赖变化只读一次。
- 页面 writeToken、revision、pending 锁、409 输入保留与刷新行为、暂停/恢复确认和取消顺序不变。候选/提醒计数、banner tone 优先级、进程信息折叠和错误展示不变。
- 三 Tab 键盘行为、动态深链优先级、运行抽屉/详情、焦点恢复、草稿回跳携带当前 Tab、各现有回调不变。Raw 正文不改；AI 输出仍只为草稿，正式写入须人工动作。

## 拆前行为测试与定向集

**先新增必要公开行为测试，在原产品基线全部通过并留存日志、命令、产品 SHA/文件指纹，然后才能改产品。** 从原公开路径挂载真实 React，可 mock fetch、控制 Promise/定时器；断言请求、signal、UI 和用户操作，不以源码字符串替代行为。已有测试充分覆盖的行为不重复堆叠。

新增测试至少覆盖以下真实缺口，可合并关联场景：

1. 延迟响应超过 3000ms 仍无同一 poll 重入；完成后才重新计时；同时验证设置读取不是周期轮询。
2. 运行筛选或详情切换、候选日期等原条件变化时旧 signal 被 abort，旧响应最后成功或失败均不覆盖新结果/错误；按实际原实现选代表条件并检查其余 effect 的同构保护，不为每一字段复制用例。
3. 功能条件关闭与卸载清 timer/abort；旧 Promise 晚到不得重新安排旧轮询或污染仍挂载的新状态。覆盖条件打开后启动，不能要求原实现不存在的清空语义。
4. 状态/计划部分失败仍显示成功部分，后续成功清错误；至少另一独立读取失败保留旧值、恢复后更新，证明不会串改其他错误区域。

如基线失败，先给主 Agent 原始复现，区分测试预期错误与既有问题；不得暗改产品或弱化断言。仅批准的等价预期在原实现验证通过后再施工。
