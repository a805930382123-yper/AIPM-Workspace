## 批次目标

用户在主导航「产品构想」中为一个新产品建立构想。按“背景 → 使用者 → 价值 → 功能 → 构想”五个区手工录入，看到确定性追溯检查，并能导出 Markdown。本批不调用模型，不包含周计划。

## 必做

1. **导航与列表**：在主导航「工作事项」之后新增「产品构想」。列表显示名称、一句话定义、状态和更新时间，默认隐藏已归档构想，可切换显示。空列表可直接新建，只需填写名称；一句话定义可选。状态分为探索中、定义中、规划中、执行中、暂停、已归档，由用户手动切换。
2. **五个区各自保存**：
   - 背景：一句话定义、业务背景、业务目标、约束条件；关联 Raw、Wiki 页和工作事项。
   - 使用者：角色卡、使用场景与任务、痛点、现有替代方案。
   - 价值：价值主张。
   - 功能：功能卡和“不做”清单。
   - 构想：北极星、目标用户范围、不做范围、成功指标、风险和里程碑。
   - 字段定义见路线图“默认分析框架”。预设角色只作为可修改的填充建议。
3. **事实依据**：痛点类型为“事实”时，必须选择本构想已关联的 Raw，并输入当前正文中逐字存在的引文（≤500 字）。其他类型不需要引文。可以按同一 Raw ID 打开原文。Raw 被删除、受限或引文不在当前正文时显示“依据失效”，不阻止阅读，也不自动改写。
4. **追溯检查**：在服务端按当前已保存内容确定性计算，随详情返回，界面可点击定位到对应条目。检查只提示、不阻止保存，0 次模型调用。
   - C1：功能（不含“不做”）没有来源价值。
   - C2：价值没有任何功能承接。
   - C3：痛点没有被任何价值覆盖。
   - C4：标为使用者或决策者的角色没有任何价值。
   - C5：MVP 中的“必须”功能，其来源价值全部是假设。
   - C6：事实依据失效。
   - C7：里程碑没有包含功能，或 MVP 中的“必须”功能没有进入任何里程碑。
5. **引用完整性**：删除被其他条目引用的角色、场景、痛点、价值或功能时，返回 `409` 并列出引用方，界面提示先解除引用。整个构想删除前需要确认，删除后移入回收目录，不再出现在列表。
6. **Markdown 导出**：内容按背景、使用者、价值、功能、构想排列。痛点按事实（附 Raw 标题与引文）、推断、待验证分节，末尾附当前追溯检查摘要。导出只生成下载内容，不写入 Raw、Wiki、Prompt 或草稿。
7. **备份**：`product-blueprints` 加入 `scripts/backup_workspace.ts` 的 `ROOTS`，恢复到新数据根后可回读；没有该目录的旧备份仍可恢复。

## 排除

## 数据与接口

- 每个构想原子保存为 `product-blueprints/<uuid>.json`，带 `revision`，写入使用 `SerialQueue` 和 `writeJsonAtomic`。删除时将完整文件移到 `product-blueprints/recycle/`。目录不存在时列表为空。读取到损坏记录时报错并保留原文件，其他记录照常列出。
- 记录主体：`id, revision, createdAt, updatedAt, title, oneLiner, status, context{background, businessGoal, constraints}, links{rawIds, wikiIds, workItemIds}, personas[], scenarios[], pains[], alternatives[], values[], features[], vision{northStar, targetScope, outOfScope, metrics[], risks[]}, milestones[]`。
- 各条目使用服务端生成的稳定 UUID，跨条目只按 ID 引用。枚举值：
  - 角色：`side: internal|external`，`relations: decision_maker|user|affected|payer`。
  - 痛点：`kind: fact|inference|question`，`severity: high|medium|low`，`evidence?: {rawId, quote}`。
  - 价值：`confidence: verified|assumed`，`validation?`。
  - 功能：`priority: must|should|could|wont`，`phase: mvp|v1|later`，`wontReason?`。
  - 里程碑：`targetWeek: YYYY-Www`。
- 暂定上限（先审时可以调整）：
  - 名称 ≤120 字，一句话定义 ≤300 字，长文本 ≤4,000 字，短文本 ≤500 字。
  - 角色 ≤30，场景 ≤100，痛点 ≤200，替代方案 ≤100，价值 ≤100，功能 ≤200，里程碑 ≤30，指标 ≤20，风险 ≤50。
  - 关联 Raw/Wiki 各 ≤100 个，工作事项 ≤50 个。
  - 单个文件 ≤2 MiB。超限给出明确错误，保留旧文件。
- 接口：
  - `GET /api/product-blueprints` → `{items}`（摘要）。
  - `POST /api/product-blueprints` 接受 `{title, oneLiner?}`。
  - `GET /api/product-blueprints/:id` → `{blueprint, checks}`。
  - `PUT /api/product-blueprints/:id` 接受 `{baseRevision, section, data}`，其中 `section` 取 `meta|context|links|personas|scenarios|pains|alternatives|values|features|vision|milestones` 之一，整区替换。
  - `DELETE /api/product-blueprints/:id` 带 `baseRevision`。
  - `GET /api/product-blueprints/:id/export` 返回 `text/markdown`。
  - 沿用工作事项 API 的本机访问约束、JSON 解析和错误格式。revision 过期时返回 `409 REVISION_CONFLICT`。保存成功后，客户端用返回的 revision 继续编辑，其他区未保存的内容保留。
- 关联与引文校验：Raw 关联沿用工作事项现有的 Raw 校验和来源门禁，Meeting 受限来源不能作为事实引文。Wiki 和工作事项只校验 ID 存在，并只读展示；对象被删除时显示不可用，不跳转到其他对象。读取构想不修改 Raw、RawState、Wiki 或工作事项。
