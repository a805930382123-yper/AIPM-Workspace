# ENG02 工作区清理与同步核实 任务卡

属于[工程整固路线图](../batches/ENG-HYGIENE-ROADMAP-20261122.md)第一批。目标：工作区里每一个已修改、已删除、未跟踪条目和根目录临时目录都有明确去向；确认本地提交已推送到远端；结束时 `git status` 干净（或只剩用户明确保留的条目），为 ENG04 全仓格式化准备干净基线。

## 评分与模式

需求明确度 1（各文件去向需用户取舍）/ 模块耦合 0（不涉及产品代码）/ 变更风险 1（误删证据不可恢复，用归档代替删除来控制）/ 历史失败 1（ENG01 已出清点建议但未执行，未跟踪文件和临时目录继续堆积）= **3，A 标准**。按 agent-router 当前规则选择模型；验收者先审计划，再由施工者执行；施工与验收为不同实例。

## 必做

**G1 远端同步核实。** 用只读 `git ls-remote origin refs/heads/main` 核对远端 HEAD 并记录时间。远端缺少本地提交时，由主 Agent 正常推送（不强推），读取对应提交的 GitHub Actions 结果。查明 post-commit 未推送的原因（网络、认证、钩子未启用、沙箱拦截等），写入报告；需要改钩子时先交用户决定。

**G2 增量清点。** 以 `git status --porcelain=v1 -uall` 和根目录 `.scratch-*`、`.test-*`、`.rn-*` 列表为全集，生成 `docs/reports/ENG02-20261122-worktree-triage.md`。每个条目或同批次条目组写明：

- 对应批次、字节数、是否被已提交的报告或测试引用；
- 公开风险（仓库为公开仓库）：第三方版权正文、真实业务或客户信息、凭据、本机绝对路径；
- 建议去向：`提交` / `归档到仓库外` / `加入 .gitignore` / `git restore 恢复` / `可再生，确认后删除` / `保留未跟踪（需理由）`；
- 6 个已修改和 7 个已删除文件附 `git diff --stat` 及一句话结论，说明是有意修复还是意外改动。

已在 ENG01 清点中判断过的条目注明沿用结论。

**G3 用户决策门。** 主 Agent 把清点按“去向 × 条目组”汇总给用户确认。**用户确认前不执行任何提交、移动、恢复或删除。**

## 验收项

- **ENG02-01** 远端核实：`git ls-remote` 实际输出与时间；推送后本地 `main` 与远端一致，推送提交的 Windows Node 22/24 CI 通过。不能推送则 BLOCKED 并写原因；post-commit 未推送原因有证据。
- **ENG02-02** 清点覆盖 100% 的 `git status --porcelain=v1 -uall` 条目和全部根目录临时目录（数量与实测一致），每项有去向和公开风险判断。
- **ENG02-03** 执行后 `git status --porcelain` 为空，或剩余条目全部在报告“用户选择保留”表中且有理由。
- **ENG02-04** 文件守恒：执行前总数 = 提交 + 归档 + 恢复 + 确认删除 + 保留。验收者对归档目录逐个重算 SHA-256，与 manifest 100% 一致。
- **ENG02-05** 新提交文件的凭据和路径扫描 0 命中或逐条复核；无新增大于 1MB 的跟踪文件。
- **ENG02-06** 回归：在清理后的干净工作树上，用隔离 `FMCG_DATA_DIR`、`FMCG_LLM_CONFIG_FILE` 和 Node 22 运行 `npm run check` 通过，证明清理没有拿掉测试依赖的文件；CI 同上。
- **ENG02-07** 根目录不再有 `.scratch-*`、`.test-*`、`.rn-*` 目录（或已列出例外）；`docs/testing.md` 有临时数据约定；`npm run hygiene` 输出与实际一致。

## 交付命令与操作

`git status --porcelain=v1 -uall`、`git ls-remote origin refs/heads/main`、`npm run hygiene`、`npm run check`（隔离环境变量）、归档 SHA 复核脚本、远端 Actions 结果读取。
