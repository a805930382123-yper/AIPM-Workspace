# WORK03 承接阶段成果与主题分析

方案交付范围仅为任务卡。产品施工尚未获批，本轮未执行产品施工、运行验收或真实模型调用。以 [WORK02](WORK02-20261107-task.md) 和[独立报告](../reports/WORK02-20261107-review.md)为已验证的功能基线。开工前由主线程记录实际 Git 基线。

暂定评分 0/2/2/0＝4。范围和验收清楚；跨事项历史、运行记录和界面；向 Provider 发送新字段且需要兼容旧客户端及备份；无本批同类失败记录。按 B 处理发送边界与兼容性，沿用用户批准的独立 Sol High 配置，规划和验收可由同一实例承担，产品施工由另一实例承担。未派产品施工。

## 使用流程

- 在原产品分析事项的「AI 分析」区填写可选的「本轮问题」，勾选本轮关联 Raw，可另外选择一条已保存的阶段成果。默认无承接，不自动选最近一轮，也不读其他历史。选择器区分「人工填写」与「带入 AI 草稿后保存」，显示保存时间、可展开的实际正文和已有的分析轮次入口。
- 发起前展示实际发送范围，包括已保存的目标、口径、已确认结论、未解问题、本轮问题、选中阶段成果及 Raw 标题和原文范围。未保存的事项字段或阶段成果编辑留在原表单，提示先保存才能用作承接；用户仍可明确使用已保存版本。本轮问题是本次执行的独立输入，填写后随发起操作发送并仅存入该轮快照，无需另存事项。
- 承接正文用于延续问题、进度、方法和待检验推断。`confirmedConclusions` 是用户在「当前情况」单独确认保存的内容。历史成果由人显式保存，正文可能含原 AI 假设或未决问题，仍是上下文。新证据与已确认结论冲突时，展示冲突和建议修正，人从「当前情况」决定是否更新。
- 结果先用简短摘要回答本轮问题，并说明相对所选成果有哪些新增发现、修正或仍无证据的判断。首轮给初步结论。随后按主题展示结论或假设、支持证据、反例、未决问题与下一步，能打开本轮原文快照。证据不足时标为待验证，不补造反例。保持观察明细可读，观察条数用于展示依据，不能代作全部事件覆盖或真实频次。结果仍是「待确认草稿」；沿用带入、编辑及明确保存阶段成果的操作，带入内容保留草稿来源、证据及未决标识，不覆盖已有编辑。

## 数据与接口

- 扩展 `POST /api/work-items/:id/analysis-runs` 的 `{baseRevision, rawIds}`，新增 `outputVersion?: 2`、`roundQuestion?: string`、`stageHistoryIndex?: number`。原请求继续返回原格式；新界面显式发送 `outputVersion: 2`，首轮或无承接也能出主题。仅 v2 接受新增上下文字段，v2 请求仅接受这五个字段。`roundQuestion` 去除首尾空白，空值视为未填写，上限 2,000 字。
- `stageHistoryIndex` 是已保存事项完整 `history` 的零基下标。服务端核对同一事项的 `baseRevision` 后，从该位置读取唯一 `kind: 'stage_result'` 的正文和来源标记。拒绝越界、非整数、非成果项、空白或超过既有 20,000 字上限的正文；旧 revision 返回 `409 REVISION_CONFLICT`，界面重新读取后提示重新选择。客户端只给下标，服务器不接受客户端提供的承接正文或任意 `runId`。现有历史为追加数组，无需历史迁移。
- v2 `run.input` 在原字段和 `sources` 外可含 `roundQuestion` 和 `stageContext: { historyIndex, at, body, source: 'manual'|'ai_assisted', analysisRunId? }`。来源由所选历史项的可选 `analysisRunId` 得出。发往模型的承接字段只保留 `body`、`source`，不附送引用轮次的输出、旧 Raw 或全历史。本地快照同时保留发送内容和追溯字段，便于 WORK04 精确复用发送视图。
- 带 AI 轮次引用的成果须解析到同事项已完成的轮次，沿 `raws.get` 与 `assertRawNotMeeting` 核查可追溯来源当前仍可发送。新 v2 运行在本机保存 `sourceRawIds`，由本轮选定 Raw ID 与承接轮次的已知来源 ID 去重合并；旧 v1 轮次从其 `input.sources` 取 ID。缺失或受限时阻止使用该承接，提示重新选择。ID 集沿用记录大小约束，仅用于发送门禁，不进入 Provider 请求，避免再次承接时丢掉已有出处。手工正文来源由人判断，系统对其执行相同的已知密钥检查。
- 保留至少 1 条、至多 8 条已关联且可读的 Raw，合计原文至多 128 KiB；保留 Meeting 来源拒绝、已知密钥检查、Provider 快照、120 秒与 128 KiB 响应上限。新增字段与现有已保存字段同样进入发送前检查，资料和承接文本按不可信数据处理。一次启动至多调用一次，沿用每事项同一时间一轮、先存运行后发送、失败与重启中断语义。
- `run.outputVersion` 缺失读作 v1。v2 输出保留 `observations`、`suggestions`、`openQuestions`，新增 `roundSummary`（1–600 字，概括本轮回答与相对承接的变化）和 `themes`（1–8 项，按材料形成少量主题）。`observations` 沿用至多 24 条、同一轮 `rawId`、连续逐字 `quote`、`observation` 校验。

| v2 每个主题字段 | 契约 |
|---|---|
| `title`, `conclusion` | 标题 1–120 字。`conclusion` 为 `{kind, text}`，`kind` 为 `evidence_supported` 或 `hypothesis`。证据不足的主题可为 `null`，此时及假设均须列出至少一个未决问题。 |
| `evidence`, `counterEvidence` | 两组均为该轮 `observations` 的零基下标，组内唯一，组间不重复。`evidence_supported` 至少引用一个支持观察；未发现反例时用空数组。 |
| `openQuestions`, `nextSteps` | 每组 0–8 条，下一步是建议，保持与未决问题分列。 |
| `confirmedConflict` | 无冲突为 `null`，否则 `{confirmedQuote, observationIndexes, suggestedRevision}`。逐字引用本轮已确认结论快照，至少引用一个有效观察，展示修订建议。 |

- 字段除另有限制外沿用现有输出文字 2,000 字上限并拒绝空白。严格结构和引用检查失败时沿用失败执行，不产生可采纳输出。结构检查只能证明引文存在及下标合法，实际语义支持由人判断，WORK04 再提供单独模型复核。
- `GET /api/work-items/:id/analysis-runs` 同时读取旧轮次和新轮次。旧观察、原文、阶段成果引用继续可读。记录留在原执行目录，沿现有备份递归白名单，无批量迁移。执行结果只写本轮记录，不改事项字段或既有阶段成果。

## 真实质量与预算

WORK02 工程独验真实请求 0；后续真实模型合成演练只覆盖对应样例，真实事项及续轮质量仍待验证。建议用户确认同一真实事项和两批可发送资料后，用不超过 2 次真实分析分别建立基线与承接续轮，记录每次资料范围、模型、耗时、实际请求数和去敏结果。核查续轮是否回应本轮问题、主题和引文是否对应、反例和未知是否保留、旧推断是否被错误当作事实。第二轮无法有意义承接时停在已取得的证据。该预算是建议，失败或中断计入获批上限，无自动重试，不继承或扩大历史额度。真实质量须单列；没有实测时写 `NOT_RUN`，fake 不能签质量通过。

本批限分析续轮与结果展示。模型二次复核、事项推进建议归 WORK04；外部触发、后台执行、自动发送、自动改稿、正式 Wiki 或 Prompt 写入、全历史拼接和通用任务引擎均在本批范围外。
