## 共通边界

Raw 正文保留原样；事实、整理、推断和待确认问题分别存储。AI 输出仅为草稿，正式 Wiki、Prompt 或新版本由用户明确操作触发。涉及 Wiki 背景时，用户显选来源，遵守现有来源门禁；反馈不隐式外发。保留累计调用账本，未来真实请求须先冻结样本、目的地、有限预算和停止条件并获授权，历史使用不清零。任何阶段不得凭静态阅读或 fake 声称真实模型质量通过。[架构与存储约定](../architecture.md)、[协作规则](../coordination.md)和[验收规约](../acceptance.md)仍适用。

## 阶段 1：条件触发核心补缺

已有 KB03 R10 的冻结范围整体 PASS；当前不安排既有核心返修。旧收据缺口、非阻断不足和会议 UI 分别保留，不把它们合并为本阶段自动施工。触发条件是出现有证据的具体阻断缺陷，或用户单独授权处理某项遗留。

候选责任：按缺陷定位具体产品服务、对应测试和任务卡，冻结所有权后实施；不得预先扩大文件范围。依赖：具体复现、受影响版本、独立验收标准及必要授权。

- **L1-01**：以最小可复现 fixture 或明确浏览器操作记录实际、预期和版本；预期可区分已知缺陷与环境阻塞。验证：定向测试或实际 UI，按缺陷选择。
- **L1-02**：修复后独立复验复现及受影响回归，分别裁决局部缺陷和相关批次整体；预期无以局部通过替代整体通过。验证：独立测试及证据复核，真实质量仅在单独授权后验证。

## 阶段 2：状态与恢复表达

[Raw 页面](../../app/pages/RawPage.tsx)已有 standard/deep 阶段、段数、累计调用和复用数，也有继续、标准覆盖失败时仅重新规划、重新生成及零调用保存恢复。缺口是把对象、阶段、已保留结果、问题和允许的下一步清楚组织，不创建通用任务引擎或改变恢复策略。候选责任：Raw 页面与必要状态映射；Prompt 工作台仅在已有状态表达确有缺口时调整。依赖：现有持久化语义，新增服务字段须先证明必要。

- **L2-01**：构造进行中、待审、失败、保存失败、正式完成五类 fixture；逐一展示真实阶段、保留结果和可用动作，失败不显示成功。验证：组件/集成及浏览器操作。
- **L2-02**：标准覆盖失败展示仅重规划条件；deep 与其他失败只展示其服务端允许的动作，明确继续与重新生成影响；预期不暗示各模式可互换。验证：定向 fixture 与 UI。
- **L2-03**：刷新、服务重启、切换 Raw 后注入迟到响应；预期恢复持久化真实状态，响应不串对象。验证：隔离数据集成及浏览器。
- **L2-04**：保存失败后显式恢复保存，计数模型请求；预期保留草稿、成功恢复且新增请求为 0。验证：隔离服务/网络探针。

## 阶段 3：首页行动事项

[首页](../../app/pages/HomePage.tsx)已有更新/综合工作流入口，但读取失败转空、待审统计只跳 Wiki、Open Audit 无动作；[统计服务](../../services/stats/index.ts)是统计而非行动契约，其部分错误转空和静态路径为代码观察，非本轮复现。[App 导航](../../app/App.tsx)已有世代与草稿定位机制，应复用。缺口是按来源事实提供可行动聚合及分源错误，不建立第二套持久任务状态。

候选责任：HomePage、App 导航、必要的窄服务端聚合及对应测试；来源服务仅按事实读取。依赖：阶段 2 的状态与动作定义；冻结四类来源和各自目标 ID/版本：Raw 整理任务、待审核草稿、更新/综合工作流、Open Audit。

- **L3-01**：构造同一事项经多个来源出现、同时含阻断和待审事项的 fixture；按事项 kind + 稳定事项 ID 去重，同一事项跨源合并。另构造共享 Raw ID 的不同待审草稿、工作流与 Audit，预期各自保留可行动入口：关联同一 Raw 不等于同一事项。阻断优先，同级按更新时间排序。验证：聚合定向测试。
- **L3-02**：四类各选一条跳转，分别断言 Raw 任务、草稿审阅、对应工作流、对应 Audit 的实际 ID 和版本；删除目标或版本变化后显示失效/重新读取，不跳到其他对象。验证：隔离集成和浏览器。
- **L3-03**：处理一条事项后刷新，预期消失或按真实状态更新；单一来源读取失败时明确显示该源失败，其他源仍可见，不显示该源为零。验证：故障 fixture 和 UI。
- **L3-04**：仪表化首页读取，预期模型请求 0、业务写入 0。验证：网络与存储探针。

## 阶段 4：快消场景模板

[模板服务](../../services/prompt-ai/service.ts)已有 7 个模板，列出的模板信息主要是元数据；[Prompt 工作台](../../app/pages/PromptAiWorkbench.tsx)已有手动 Brief 与预览。缺口是将实际高频场景映射到既有 ID 或补少量必要结构，而非重做生成器。首轮选择 3–5 个：经销商访谈、门店补货、指标口径、业务问题转 AI 需求、材料阅读；先逐一盘点并冻结复用/调整/新增 ID，避免同名重复。每项明确所需输入、预期产出、来源与事实约束、缺失信息待确认。

候选责任：prompt-ai 模板定义与工作台字段提示、对应测试；依赖：任务卡确定映射及是否改变模型提示。

- **L4-01**：对 3–5 个场景断言 ID 唯一、已有模板兼容，输入/输出/事实约束明确，缺项保留待确认。验证：模板契约测试及 UI 审阅。
- **L4-02**：手动编辑 Brief、预览并选择保存；预期手动模式可用、无自动收藏。选择 Wiki 背景时验证显选及来源门禁，未选内容不发送。验证：隔离集成与浏览器。
- **L4-03**：若改动模型提示，实施前冻结有限真实样本、目的地、累计预算及停止条件并单独授权；逐个获批样本独立核查是否覆盖冻结的输入、预期产出和事实约束，缺失信息是否明确待确认，以及是否存在编造或来源错绑；每个样本全部必选项通过才签质量 PASS，失败保留，不能以其他样本补偿。样本及判定表在未来任务卡冻结。未执行时标未测，不以静态/fake 代替质量 PASS。验证：获批后的真实质量验收。

## 阶段 5：使用反馈（条件启动）

[Prompt 存储](../../services/prompt/store.ts)已有版本快照；静态阅读未发现使用反馈实体。仅在实际使用确认需求后启动。首版由用户手动记录 Prompt 稳定 ID、使用版本、日期、场景、效果、问题/有效部分和改进建议；查看、编辑、删除均明确操作，不自动修改 Prompt 或发送 Provider。

候选责任：Prompt 详情、服务/API、持久化、备份与导出及测试。任务卡须先冻结反馈 schema、目录、ID、版本关联、删除与重复提交规则；现有[备份白名单](../architecture.md)包含 knowledge/prompts/drafts/state/meetings，新增路径必须纳入可恢复范围，并避免混入 Prompt 数量、Wiki 搜索和知识日志。

- **L5-01**：同一 Prompt 两版本各创建反馈，更新当前版本后重启；预期反馈仍归原 ID/版本，CRUD 和重复提交符合冻结规则。验证：存储集成及浏览器。
- **L5-02**：备份、恢复至隔离新根并导出，比较反馈与原版本关联；旧无反馈记录仍可读，删除及恢复规则一致。验证：备份恢复集成。
- **L5-03**：创建/编辑/删除反馈前后比较 Prompt 和 Wiki 统计，并记录网络；预期计数不污染、无自动外发或新版本。验证：服务集成及网络探针。

## 阶段 6：周期回顾（可选）

仅在阶段 5 形成真实记录且用户需要时启动；按用户主动打开的周期确定性汇总正式知识、待处理事项及反馈，不生成 AI 报告或定时通知。候选责任：窄聚合服务、回顾页面和测试；沿用首页同源口径，不新增虚构指标。

- **L6-01**：以 Asia/Shanghai 周期起止前后各一条记录构造 fixture，断言边界归属、数字与可追溯明细一致，同源统计与首页一致。验证：时区和聚合测试。
- **L6-02**：删除/回收记录及无反馈 fixture；预期按冻结口径排除或明确标示，空状态显示无记录，不补造。验证：集成和 UI。
- **L6-03**：打开回顾并统计模型请求，预期为 0。验证：网络探针。
