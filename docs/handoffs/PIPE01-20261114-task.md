# PIPE01 资讯→Raw→知识草稿自动流水线 任务卡

属于 [AI 自动化路线图](../batches/AUTO-ROADMAP-20261114.md) 阶段 1。目标：每天自动准备资讯并由 AI 预筛，用户在一个收件箱里确认要入库的条目；确认后系统自动保存 Raw 并发起整理，生成的草稿进入首页待审队列；正式写入 Wiki 仍由用户在既有审核流程中确认。

```mermaid
flowchart LR
  A["定时任务 news.daily"] --> B["NewsService.ensure 抓取与缓存"]
  B --> C["AI 相关性预筛"]
  C --> D["候选收件箱"]
  D -- "用户确认（单条或批量）" --> E["保存 Raw（既有幂等路径）"]
  E --> F["自动发起标准整理"]
  F --> G["草稿进入首页待审"]
  G -- "用户审核确认" --> H["正式 Wiki（既有事务）"]
  D -- "忽略 / 稍后" --> D
```

## 评分与模式

需求明确度 1（流程已冻结，预筛分类口径由规划者细化）/ 模块耦合 2（调度器、资讯、Raw、整理任务、草稿、首页、Provider）/ 变更风险 2（自动发起 Raw 创建与整理，涉及来源完整性与真实外部请求）/ 历史失败 1（资讯源可用性波动：PwC 超时、CCFA 证书过期）= **6，B**：Astra 规划与独立验收，Sol High 施工。

## 已冻结的产品决定（来自用户 2026-11-14 答复）

1. **Raw 创建须用户确认。** 自动化只抓取、预筛、排队；不得未经确认创建 Raw。
2. **确认即授权整理。** 确认对话框中“确认后自动整理”默认勾选（模式默认 standard，可改 deep 或取消勾选）；勾选时，确认动作同时授权该条目的 Raw 保存与一次整理发起。
3. **正式写入不变。** 草稿到 Wiki 只走既有逐页人工审核与确认事务；本批不新增任何自动确认路径。
4. **不设预算上限**，但抓取、预筛、整理三类调用全部计入运行记录用量（RUN01 机制）。
5. 保存到 Raw 的内容沿用 NEWS 既有规则：只保存已取得的摘录或来源摘要及来源元数据（原期刊日期、证据等级），不抓取付费全文，不把摘要冒充原文。

## 必做

**P1 定时任务 `news.daily`。** 在 RUN01 调度器注册：默认每天 07:30（Asia/Shanghai）、`catchUp:true`、默认启用（全局暂停仍有效）。进程内调用 `NewsService.ensure()`，复用按日缓存、单源/总量配额、来源健康与失败隔离；已准备过的当天不重复外部抓取。运行记录步骤含各来源健康状态、条目数、短缺原因。手动“立即运行”同样可用。CCFA 等默认关闭来源保持关闭。

**P2 AI 相关性预筛。** 对当天新条目（快消研报与 AI 前沿两栏）做批量结构化调用（每批条目数由规划者定，单次调用失败不影响其他批）：
- 输出每条：`relevance`（0–3）、`categories`（从固定枚举选：品类、渠道、消费者、竞品与品牌、政策法规、宏观与零售数据、AI 工具与方法、其他）、`reason`（≤120 字，只基于给定摘录）、`suggestedMode`（standard/deep）。
- 系统提示要求不得补充未提供的事实、链接或日期；严格 schema 校验、条目 ID 一一对应、密钥扫描；不合规整批记为预筛失败。
- 用户可在自动化页编辑“关注主题”列表（短文本，最多 20 条），作为预筛输入；默认按快消产品经理常见关注点给出初始值并标注可改。
- 结果存 `state/automation/news-candidates/<date>.json`，**不修改资讯缓存与 Raw**。预筛失败或未配置 Provider 时，候选仍完整展示并标“未预筛”，不隐藏、不伪造分数。
- 预筛受 `FMCG_NEWS_AI_ENABLED` 以外的独立开关控制（自动化页任务设置），默认开启；关闭时 0 模型调用。

**P3 候选收件箱 UI。** 位于“自动化”页（首页卡片可直达）：
- 按日期分组，默认今日；按相关性排序，显示标题、来源、发布日期、证据等级（摘录/来源摘要）、摘录展开、AI 理由与分类（明确标注“AI 预筛，仅供参考”）、已保存状态。
- 操作：确认入库（单条/多选批量）、忽略（持久化，可在“已忽略”中恢复）、稍后（保留在收件箱）。已在 Raw 的条目显示“已入库”并链接到 Raw，不可重复确认。
- 确认对话框列出将保存的条目、每条将写入 Raw 的内容类型、是否自动整理及模式；用户确认后才执行。

**P4 确认执行与整理编排。**
- 每条确认依次：沿既有 `NewsRawSave` 幂等路径保存 Raw（原期刊日期、来源字段、证据等级不变）→ 勾选整理时，通过既有 runner 在 Wiki 锁下发起整理任务。
- 编排作为自动化运行 `pipeline.organize` 记录：每条的 candidateId→rawId→jobId→draftId 链接、逐条状态与错误、用量。整理并发上限默认 2（可在任务设置调整）；超出部分排队。
- 部分失败可见且可单独重试：Raw 已保存但整理失败 → “重试整理”不重复创建 Raw；Raw 保存失败 → 不发起整理。
- 进程重启后：已确认但尚未开始的条目继续排队执行（用户已授权）；**已开始但被中断的整理任务沿既有规则标记中断，需用户显式继续**，不自动重发。
- 不绕过既有门禁：会议来源限制、Raw 来源完整性、密钥扫描、草稿 revision 与确认事务全部照常生效。

**P5 首页集成。** 首页增加“今日资讯流水线”卡：已抓取 N、待确认 M、整理中 K、待审草稿 D、失败 F，各项可跳转。整理产生的草稿继续出现在 AUTO02 既有待审卡片，不新建第二套审核入口。

**P6 文档。** README 增加“自动资讯流水线”使用说明（何时运行、如何确认、确认意味着什么、如何暂停、费用说明）；`docs/architecture.md` 增加 PIPE01 小节。

## 排除

## 验收项

- **PIPE01-01** 定时与补跑：fake 时钟下 07:30 触发、错过后开机补跑一次、同日不重复外部抓取、暂停时 skipped；真实常驻模式下把计划设为 2 分钟后，实际自动触发一次（真实来源，TEMP 数据根）。
- **PIPE01-02** 预筛：schema 正反例（多余字段、ID 不对应、越界分数、超长理由、密钥）均整批拒绝且候选仍可见；未配置 Provider/开关关闭时 0 调用；真实 Provider 对当天真实候选完成预筛，验收者抽查 ≥5 条理由不含摘录以外的事实。
- **PIPE01-03** 确认门禁：未确认时 Raw 数量不变（磁盘核对）；忽略/稍后/恢复持久化；已入库条目不可重复确认；批量确认中途失败时已成功项保留、失败项可重试且不重复 Raw。
- **PIPE01-04** Raw 与来源：确认入库的 Raw 正文与资讯摘录逐字一致，来源/原期刊日期/证据等级正确；与手动“保存来源摘录到 Raw”结果一致（幂等，不产生第二条）。
- **PIPE01-05** 整理编排：并发上限生效；Raw 已存整理失败可单独重试；重启后排队项继续、已中断任务需显式继续且无自动重发；链接 candidate→raw→job→draft 完整可追溯。
- **PIPE01-06** 正式写入边界：整个流水线运行后正式 Wiki 与 Prompt 文件 SHA 不变、正式事务数 0；仅在验收者于 UI 中审核并确认某个草稿后才出现对应 Wiki 写入。
- **PIPE01-07** 真实端到端（TEMP 数据根，真实来源与真实 Provider，无上限但全程记账）：一次自动触发 → 预筛 → 在 UI 确认 ≥2 条（至少 1 条快消研报、1 条 AI 前沿）→ 2 条 Raw → 2 份草稿出现在首页待审 → 验收者审核确认 1 份写入 TEMP Wiki。报告列出全部请求数/token/未知用量、各步骤耗时、截图（1440/390）。来源因外部原因不可用时如实记录，可用当天其他可用来源完成，不绕过 TLS 或站点限制。
- **PIPE01-08** 用量：运行记录中抓取、预筛、整理三类用量与 Provider fake 计数一致（工程验证）；真实运行用量如实，未知用量单列。
- **PIPE01-09** `npm run check` 通过、CI 绿；若 EVAL01 已交付，`news-relevance` 回放用例 ≥10 条并通过阈值。

### 2026-11-16 开工冻结（Astra Medium 规划；6 分 / B）

此补充细化上文，不降低 PIPE01-01～09。施工为独立 Sol High 实例；本规划者不改产品代码，交接后承担独立验收。EVAL01 已 PASS，故 news-relevance ≥10 条回放为必选。

**预筛契约。** 每批最多 10 条，按资讯原顺序分批，失败不阻断后续批；不自动重试模型失败。输入仅 candidateId、标题、来源、日期、证据类型、原摘录及关注主题，正文视为数据而非指令。candidateId 为 date/section/itemId 的稳定组合，保留来源 URL 用于既有去重但不要求模型生成 URL。输出为严格对象及严格数组项，ID 集合与本批完全相等且无重复；categories 为非空去重枚举数组，reason 非空且最多 120 Unicode 字符，relevance 为整数 0–3。0=与关注主题无直接关联，1=间接背景，2=直接相关，3=与关注主题高度相关且有具体可用材料；分数是相关性，不是事实可信度。suggestedMode 仅建议，确认默认 standard 不被 AI 自动改为 deep。关注主题最多 20 条，每条 trim 后 1–80 字符；默认“快消品类与品牌”“渠道与零售”“消费者趋势”“AI 产品与工作方法”。

预筛独立开关默认开启，已完成候选不因刷新或重复日任务再次请求；失败/未配置保持 unscored，保留失败原因。关注主题修改仅影响以后尚未预筛的条目，不隐式重发。用户已确认低分默认折叠并明确数量、仍可展开；未预筛不可归入低分折叠。

**服务及 HTTP 边界。** 新 Pipeline 服务由 server/index.ts 注入同一 NewsService、既有 NewsRawSave 路径、runner、Wiki 锁和 Provider factory；不得 HTTP 回调自身。候选读写走 /api/automation 下既有 Origin/JSON/token 门禁。冻结语义接口为：GET candidates（date 可选，默认上海今日）；GET/PATCH pipeline settings（revision、preScreenEnabled、topics、concurrency，后者整数 1–4 默认 2）；POST candidates confirm（requestId、candidateIds、organize、mode）；POST candidate disposition（ignore/later/restore）；POST candidate retry-organize。具体 URL 后缀/TS 名称可由施工者与既有代码对齐，交接须列明，以上输入与语义不得省略。服务端从持久候选读取内容，客户端不传或覆盖正文/评分/来源。缺失 ID 或非法字段在任何副作用前拒绝。列表不触发抓取、预筛或 Raw 写入。

**持久化与恢复。** 每日候选文件 schemaVersion:1，保存不可变资讯快照、预筛结果/失败、用户 disposition，以及确认授权（requestId、organize、mode、时间）与 rawId/jobId/draftId、阶段/错误。设置单独存 state/automation 下并用 revision 防止旧表单覆盖。沿现有串行队列及原子文件写入，不新增数据库或通用工作流引擎。先持久化用户授权再执行；重复 requestId/已确认项返回已有链路，不再次发起整理。不同日期同 URL 仍复用 NewsRawSave 的 Raw 身份；已入库条目展示链接且不得再次确认。手动资讯保存与流水线共享同一保存实例/串行入口，避免两个独立队列争写同 URL 收据。

确认队列逐条允许部分成功；保存 Raw 失败不得排整理。启动整理前持久化 started 与稳定 job 身份，并复用既有 runner 恢复规则，重启不自动重发 started 项；尚未开始且已授权项继续。重试整理必须显式操作且仅作用该条，不重新保存 Raw。设置并发上限限制活跃整理；Wiki 锁可使实际更低，锁冲突保留排队，不丢任务或偷偷绕过锁。全局暂停阻止新后台队列启动，保留已授权队列。运行记录不得在后台 job 未结束时伪报成功；每条链路及失败阶段可查。

**用量及首页。** news.daily 记录抓取与预筛，pipeline.organize 记录整理；抓取请求计数与模型请求计数须可分别识别（阶段步骤/附加统计均可），同次请求不重复计入两个运行。未知 token 单列，不用 0 代表已知免费。首页数字从持久候选/真实 job/draft 投影：今日抓取总数、待确认（排除忽略及已确认，包含稍后）、排队/整理中、有效未审草稿、失败条目；点击落到匹配过滤，草稿复用现有待审入口。
