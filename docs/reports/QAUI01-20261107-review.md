## 独立实测

| 项目 | 证据 |
|---|---|
| Q01 布局 | Chrome 156.0.8078.80 的 1440px、1024px 上左侧提问、右侧回答，阅读区更宽。390px 按提问、回答、依据、预览排列，问答区内宽 356px；长词和长标题换行，无横向溢出。桌面空态提示可直接开始提问。 |
| Q02 正文与依据 | 事实、推断、分歧分类清晰，正文短编号可复用并对应独立的依据区。依据区显示标题、类型、版本或 Raw 原文区间及引文。三分类与极长词使用单独浏览器页，在真实当前回答 HTTP 响应上补充合成展示样本；这页仅用于布局与编号断言。 |
| Q03 引用 | 在 Chrome 用 Tab/Enter 和鼠标从正文编号定位对应依据；焦点及边框可见。依据按钮经过原 citation API 打开正确 Wiki 或 Raw；Raw 高亮对应原句、起止偏移及原文 SHA。改动隔离 Wiki 后，旧引用经真实 API 返回 409，显示“回答依据页已变化”。 |
| Q04 选段与草稿 | 保存全部预览显示全部正文、事实、推断和依据。跨段选区含 `[1][2][3]`，预览和请求中的 selectedText 仅有正文，提交保存保留正确的两项 sectionId 和三项 citationId。取消没有草稿；明确生成后才写入一份维护草稿，从问答入口可以打开审核。保存前后的正式 Wiki、Raw 和 Raw 处理状态文件哈希一致。 |
| Q05 状态与回归 | 提问和保存处理中有阶段反馈，重复提交控件禁用。提问失败标明原回答仍对应旧问题，重试由用户显式触发并复用请求 ID。依据不足显示无引用，保存禁用，模拟模型调用数无增加。草稿写入故障保留编辑；重试复用提议和保存请求。页面异常 0。 |

首轮直接在 Chrome 缩放后读取布局时撞到全局减弱动态效果样式的过渡帧，读得 `.main` 仍使用桌面边距。390px 直接开页和等待两个绘制帧的复测均恢复正常。首轮时序证据存于本机 `node_modules/.cache/qaui01-review/first-review-*`。稳定后人工看图发现窄屏引用编号拆行，收起问答按钮也折行。施工仅固定编号及收起按钮为单行，最终重测三种宽度、长标题换行与窄屏引用焦点，保留同 TSX 的完整 HTTP 与选段回归证据。修复前窄屏图存于本机 `node_modules/.cache/qaui01-review/before-repair-review-long-content-390.png`。
