# KB02 两项真实质量问题返修方案

日期：2026-10-22。状态：方案已编制，未施工、未调用真实模型；不改变KB02整体FAIL。依据：[本轮独立复验](KB02-FINAL-AUDIT-20261022-acceptance.md)。累计真实调用82/200、剩118；Prompt15/24独立。

## 目标与顺序

只解决F-KB02-FINAL-01（P1长文非业务片段误分类）和F-KB02-FINAL-02（P2更新单边声明误称双方一致）。先冻结失败样本与接口，再分别实施两项最小修改、完成离线回归、冻结工程版本，最后独立真实复验。施工自测不得关闭真实质量缺陷。

## A. 长文分类返修

### 已证实的问题

当前knowledge-extraction.ts已有“先业务相关性、后fragment歧义”的指令，但真实模型仍把第13段c13-a0272选入ambiguous facts。该片段由截断排版说明与下一附录标题连在一起构成；不是业务陈述。knowledge-atoms.ts按标点/换行/512字符切片，不保证每条都是语义完整句。规划遗漏f-c13-4是下游暴露；覆盖校验本身正确。

### 最小修改

1. 在提取请求中明确：atom可能包含多个相邻非业务片段；“截断排版说明＋下一标题”仍是非业务，不能因为混合、截断或无法补全而转成业务歧义。业务歧义必须以存在业务陈述为前提。
2. 增加成对示例：纯非业务拼接片段应不选或进入sourceNotes；含真实经营数值、否定、未知或未来业务边界的相似片段必须保留。示例不得使用本轮固定atom ID、区域13/14或附录编号作为判断条件。
3. 检查发送的目录与fragment标记，优先保持现有原文切片和ID契约。仅当离线最小复现证明边界缺陷必须修复时，才提出内容中立的切分调整及其影响；不得通过业务关键词黑名单或删除原文解决分类。
4. 提取规则修订进入rulesVersion指纹。本轮含错误事实的14段旧检查点不可直接用于新规则；明确拒绝旧指纹并保留原件，后续显式restart从头运行。旧已完成草稿保持可读。
5. 严格schema、来源声明互斥、覆盖校验保持。不得在模型返回后偷偷删除/改分类、把非业务事实硬塞进规划页、放宽校验或自动重试。

范围：services/llm/knowledge-extraction.ts、services/llm/rules.ts、必要的新默认回归。knowledge-atoms.ts不是默认必改项，确需变更先交边界影响说明。

### 回归与关闭条件

- 保存本轮真实失败响应及其完整请求目录，建立可溯源夹具；旧seq62及Q01格式反例继续保留。
- 覆盖非业务拼接、单独标题、完整/截断排版说明、业务fragment、业务否定/未上线/未来建议、包含“说明/虚构”等字样的真实业务陈述。
- 验证请求规则、合法响应组装、严格拒绝行为及旧指纹409零外发零写入。fake按预设返回正确分类只能证明机制，不证明模型理解。
- 独立真实复验必须使用原106400字符全文：14段成功、全部业务事实规划覆盖、14区域数值/日期正确、业务栏与摘要不含排版声明、未知/未来边界正确、Raw与引用准确，并在浏览器查看最终草稿。
- 纯非业务片段仍被模型选入facts时，本项不通过；不能将后续一次偶然成功覆盖已观察的未解决失败。

## B. 更新来源归属返修

### 已证实的问题

knowledge-workflows.ts/createUpdate目前只要求agreement每条text＋新来源evidenceId，服务端验证ID存在及引用位置正确。它没有证明该陈述同时由旧内容和新来源支持。真实输出把旧资料的“门店数不能解释为销量”扩写成“两侧均强调”，新来源全文无此声明。

### 最小修改

1. 明确agreement只表达两侧都支持的最小共同命题。一条复合句含两个断言时分别判断，不能因共同支持其中一部分就把另一部分也写成共同观点。
2. 明确“新来源未提及”不等于“新来源同意”。旧侧独有内容保留在existing；新侧独有且有证据的内容进入suggestedAdditions；无法证明一致则不生成agreement，可保留待确认问题。禁止以“均/双方/两侧”等措辞扩大来源支持。
3. 增加正反示例：两侧都有100家可列一致；仅旧侧说门店数不等于销量不可列一致；20%与30%必须列冲突；“不知道/未上线/将来建议”不能改成肯定事实。
4. 增强agreement的双侧定位约束：为旧Wiki当前revision正文构造只读定位目录，生成请求要求agreement另选旧侧定位ID，同时选择现有新侧evidenceId。服务端严格校验两侧ID分别属于本次绑定的旧Wiki版本和选中建议；缺侧、未知ID、跨目标或错版本直接拒绝，不自动补ID。仅更新请求的内部响应契约改变，synthesis契约不跟随扩改。
5. 双侧定位只能证明选中了两侧原文，不能自动证明语义一致；真实人工语义核对仍是必选门禁。旧侧定位作为本次校验/诊断依据，现有workflow.baseWiki快照继续保留；优先不改变持久化sections/evidence及UI/API形状。若需要额外持久化字段，先明确旧记录兼容方案，不能静默扩接口。

范围：services/wiki/knowledge-workflows.ts及必要窄定位助手、新回归。保留旧Wiki正文、人工备注、双来源、显式确认、修订冲突与幂等保存行为；不借本项重写综合功能或存储队列。

### 回归与关闭条件

- 原单边声明误称双边的输出保存为失败夹具；新双侧契约下缺旧侧ID必须拒绝，不能称结构拒绝已经解决语义。
- 合法双侧ID、缺侧/错侧/未知ID/错版本、合法同义共同陈述、单边声明、复合句部分支持、20%/30%冲突分别覆盖。语义样本同时进入真实复验清单。
- 确认前Wiki不变；确认后旧正文与KB02_HUMAN保留，两份Raw来源可查；刷新/重启可读，重复确认不重复写入。
- 独立真实短文＋补充更新及浏览器候选→选目标→预览→确认→刷新回读必须完成。agreement逐条与两侧材料核对，不能只验证关键字符串存在。
