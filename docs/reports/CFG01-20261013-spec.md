## FCFG-SP01：P1，环境覆盖后的摘要可泄漏本机旧凭证

位置：`services/llm/config.ts:35–43,63–68`；`services/llm/config-manager.ts:22–24`。

要求：固定接口第 3/7/8 项及 C04，摘要只返回安全地址/模型，异常配置文件/环境摘要不得泄漏已知凭证。

复现：临时文件中 `FMCG_LLM_API_KEY=local-fixture-value`，地址路径与模型也含 `local-fixture-value`；仅环境 Key 覆盖为 `env-fixture-value`，调用 manager.get。实际 `environmentLocked=true`，但 JSON 摘要含本机旧 Key。manager 已读取本机原始字节，却仅把 effective Key 交给 llmConfigSummary；安全检查遗漏仍保存在本机文件中的凭证。只读环境锁不能防止此泄漏。

实际探针输出：

```json
{"probe":"environment-overrides-local-key-in-public-field","leakedLocalKey":true,"locked":true}
```

建议：摘要校验收集所有当前非空环境/本机凭证，过滤各可读字段；有效 Provider 构造也应拒绝把这些已知凭证放入可读模型/地址。不要把旧 Key 返回前端以执行检查。

## FCFG-SP02：P1，revision 校验之后的外部编辑会被覆盖

位置：`services/llm/config-manager.ts:33–49`。

要求：固定接口第 2/3 项、C02，外部改文件返回 409，无旧文件破坏或假成功。

复现：已取得合法 revision 的保存中，用 `node:fs/promises.writeFile` 的隔离 hook，在第一次 `.tmp` 写入之前向正式夹具文件写入 `# EXTERNAL-EDIT` 与一套完整新配置。hook 只是控制另一写入者的时序，随后恢复真实 writeFile。实际保存仍成功，模型变为 `next`，外部配置及其注释消失。队列只约束本 manager 的写入；checkWritable 后到 rename 之间没有 revision/字节复核。

实际探针输出：

```json
{"probe":"external-edit-before-temp-write","injected":true,"saveSucceeded":true,"model":"next","externalEditPreserved":false}
```

建议：revision 校验和用于改写的输入必须来自同一快照；临时文件准备后、提交前复核源文件及相关环境状态，检测变化即 409 并清理临时文件。验证 save 和 clear 均不会覆盖该外部变化。

## FCFG-SP03：P2，首尾引号 Key 保存成功但有效凭证改变

位置：`services/llm/config-manager.ts:39,43,62–64`；`services/llm/config.ts:26–27,59–61`。

要求：首次/替换 Key 保存后有效生效，失败不得伪装成功。

复现：保存 API Key 字符串 `"quote-fixture"`（字符串的两端引号属于输入值），校验接受，save 返回 `configured=true`。dotenv 序列化未转义，readLocalEnvFile 剥掉首尾引号，实际 Provider Key 变为 `quote-fixture`。模型字符串存在同类往返风险。此输入没有违反当前公开的非空、单行、长度限制。

实际探针输出：

```json
{"probe":"quoted-key-roundtrip","saveSucceeded":true,"keyPreserved":false,"effectiveEqualsUnquoted":true}
```

建议：采用与 reader 一致、可往返的编码，或在写入前明确拒绝不能往返的输入；不得以 200 表示保存了不同的凭证。

## FCFG-SP04：P2，初始/重新读取的迟到响应会回退配置或丢掉编辑

位置：`app/pages/SettingsPage.tsx:20–30,79–81`。

要求：设置页 busy 防重复、卸载/迟到请求与输入变更隔离，失败合理可重试。

复现 A：初始 GET1 待决，用户点击重新读取产生 GET2；GET2 先返回 `new-model`，GET1 之后返回 `old-model`，页面回退到旧摘要及旧 revision。useEffect 的 active 只能防卸载，不参与 sequence 校验。

复现 B：reload 待决期间输入仍可编辑；模型改为 `user-unsaved-edit`，reload 返回 `server-model` 后覆盖该编辑。onChange 不使 reload 的 sequence 失效，reload 也未管理读取 busy。

jsdom 实际输出：

```json
{"probe":"initial-get-late-after-reload","newShown":"new-model","finalShown":"old-model","staleOverwrite":true}
{"probe":"input-change-during-reload","editShown":"user-unsaved-edit","finalShown":"server-model","editLost":true}
```

建议：初始读取与所有 reload/操作统一使用请求代次；读取过程应有明确 busy/编辑策略，或使输入变更令旧结果失效，避免覆盖用户的新内容。补充初始迟到、读取迟到、编辑及卸载测试。

## FCFG-SP05：P2，配置读取故障阻断全部手动路由

位置：`server/index.ts:68–70,110,152–154`。

要求：固定接口第 9 项，没有有效配置时只拒绝 AI，手动功能仍可用。

复现：真实隔离 server 以空配置文件成功启动，GET `/api/stats` 为 200；随后将夹具配置文件替换为目录以制造明确 read failure。GET `/api/health` 和 GET `/api/stats` 都变为 500 `CONFIG_READ_FAILED`，尚未进入各手动路由。所有请求都经过 providerFactory，而 loadConfig 读取错误在其 try/catch 之外传播。启动时同类读取错误也会在 listen 之前抛出。

实际 HTTP 探针输出：

```json
{"probe":"configuration-read-failure-manual-route","beforeStatus":200,"healthStatus":500,"statsStatus":500,"errorCode":"CONFIG_READ_FAILED"}
```

建议：把 Provider 读取故障限制在 AI/config 操作的错误表面，并明确保留手动路由可用；配置管理 GET/写入仍须明确报错，不能把故障伪装成缺文件或覆盖它。

## FCFG-SP06：P2，连接测试的错误响应不受体积预算限制

位置：本批新增调用 `server/llm-config-api.ts:54`；依赖 `services/llm/provider.ts:132–133,173–174`。

要求：固定接口第 6 项、C03，一条测试请求受最多 15 秒和响应体预算限制。

复现：用真实 OpenAiCompatibleProvider，maxOutputBytes=4096；fetch 的 Response fixture 是 401、每段 8192 字节、总 65536 字节流。实际完整读了 65536 字节，再返回 `LLM_AUTH_FAILED`。success 分支的 readCapped 才执行预算；httpError 的 response.text 无上限。超时约束不能替代字节预算。

实际探针输出：

```json
{"probe":"error-response-budget","budget":4096,"consumed":65536,"errorCode":"LLM_AUTH_FAILED","budgetExceeded":true}
```

建议：错误响应同样以预算读取/取消流，再做现有错误分类与脱敏。依赖 provider.ts 虽未在本批初始所有权内，但本批新测试契约依赖此行为；修复需由主 Agent 明确授权最小依赖变更。
