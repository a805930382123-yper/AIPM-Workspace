## 冻结接口

DraftRecord 增加可选 structuredNote；缺省保持旧记录语义，不迁移、不自动填空结构。独立契约版本1，包含 version、orientation、sections；section 包含唯一 id、title、question、blocks。正文契约使用严格未知字段拒绝、有界字符串/数组。具体合理上限由施工常量集中声明并测边界；不复制后续流水线 coverage/document/suggested_pages 契约。
五类 type：paragraph(text)、list(items)、table(title/headings/rows)、path_diagram(title/nodes/edges)、callout(title/text)。四类 role：source_supported、reorganized、supplementary、needs_verification。所有承载正文的叶项带 role/factIds，needs_verification 带非空 reason；paragraph/callout 在 block 级，list 在 item 级，table 在 row 级，path 的节点/边各自声明角色与引用。容器不另声明相冲突的角色。节点用稳定 id/text，边 from/to 引用节点 ID；不使用模型可执行 Mermaid。
source_supported/reorganized 必须有非空有效 factIds；supplementary 不冒充事实、不进入 source_facts；needs_verification 必须展示原因。引用有效性由调用者提供 fact ID 集合验证；草稿保存/读盘以该草稿 humanReview 来源 unit records 的 fact ID 目录为上下文，不能仅验证字符串形状或将模型自报 ID 当证据。旧草稿无该字段无需具备新目录。无法确定来源目录时明确拒绝带字段的新记录，不能静默删除字段。表格每行 cell 数等于 headings，节点/章节 ID 唯一，边端点存在。
纯函数解析/校验与 renderStructuredNote 输出稳定 Markdown；正文按纯文本转义，标题、竖线、反引号、换行、HTML、链接样式输入不能改变结构或隐藏角色。保留中文、数值、单位及顺序。四角色均有可见中文标签，引用显示真实 ID，补充标签严格为“补充知识，未经原文支持”。不得自动改写事实文本或制造引用。

## 第一轮保存安全与兼容

现有 candidateContent 明确投影可写内容，新增字段必须纳入摘要（缺省时保持旧摘要），任何新增/修改均使旧审批失效。已有 assertReviewed 是 CommitStore 正式入口的主要门禁，workflow update 对输入 draft 的检查也必须覆盖。
本轮不提供 structuredNote 的 HTTP 编辑/创建入口，不把它加入 Source/body，不允许现有宽松对象扩展将它偷偷保存后确认。携带 structuredNote 的草稿可严格读回/保留，但任何正式 create/update/准备提交一律明确拒绝“结构化笔记尚未开放确认”，即便旧 HUMAN 审批齐全亦拒绝；不能直接忽略新内容然后报确认成功。普通旧草稿、已完成旧操作幂等语义保持。现有 HTTP patch 若收到新字段须明确拒绝，不静默接受；不得借本轮增加自动审批或重建来源目录。

## 渲染与静态视觉边界

不改依赖。现有 react-markdown 不支持 GFM 表格，不能把管道字符串快照称为实际表格显示通过。本轮 table 使用 CommonMark 行级列名列表展示，每行保留所有“列名：值”、行级角色和证据；这是明确的兼容显示决策，网格表格产品呈现留 R3。path 使用节点及箭头关系列表，保留节点和边证据。fixture 覆盖全部五类型/四角色及多列中文长内容。
脚本以 renderStructuredNote 的真实返回值送入已安装 react-markdown/react-dom server 生成静态 HTML，输出到系统临时目录。验收者通过浏览器实际打开检查五类内容、层级、列名值关联、长行换行与全部来源标签；保留截图/实际操作证据。不把独立静态页称为产品 UI 完成，不要求新增产品交互。
