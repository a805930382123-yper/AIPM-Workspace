# ENG01 工程基线与开发自动化地基 任务卡

属于 [AI 自动化路线图](../batches/AUTO-ROADMAP-20261114.md) 阶段 0。目标是让后续 Agent 能在**绿色基线**上自动施工和回归：任何改动都能用一条命令和一次 CI 判断是否破坏既有功能，并且 Agent 每轮不必加载数百 KB 历史台账。

## 评分与模式

需求明确度 0（目标与验收清楚）/ 模块耦合 1（涉及多个测试与文档，但不改产品行为）/ 变更风险 1（修测试可能掩盖真实回归、文档迁移可能丢历史）/ 历史失败 1（COMPAT01 修过一轮，`lw01-raw-ui` 等损坏仍在）= **3，A 标准**：Astra 规划，Sol High 先审计划，Terra High 施工，不同实例 Sol High 独立验收。

## 必做

**E1 类型检查全绿。** 修复上述 10 个错误，使 `tsc -b` 0 诊断。优先修复测试文件本身（损坏首字符、过期类型、fixture 字段）。不得通过新增 `exclude`、`// @ts-ignore`、`any` 断言或降低 `tsconfig` 严格度来消除错误；确需排除的文件须在报告中逐个说明原因并经验收者认可。

**E2 默认测试全绿。** `npm test` 0 失败。对每个失败归类为：测试文件损坏 / fixture 或断言过期 / 环境依赖（网络、时区、Node 版本）/ 真实产品缺陷。
- 前三类在测试侧修复；环境依赖须改为确定性（固定时钟、本地 fake、隔离目录）或移出默认 glob 并在 `docs/testing.md` 登记运行方式。
- **真实产品缺陷不在本批静默修复**：记录复现与影响，暂停交主线程裁决（可能扩大范围或另开批次）。
- 允许的跳过须集中登记在 `docs/testing.md` 的“已知跳过”表（测试名、原因、负责批次、登记日期），验收者核对数量；不得用跳过达成“全绿”而不登记。

**E3 统一检查命令。** `package.json` 增加：`typecheck`（`tsc -b`）、`check`（typecheck → test → build 依次执行，任一失败即失败）。`npm run build` 保持可在空 env 下成功。新增 `docs/testing.md`：默认测试范围、验收脚本（`tests/acceptance/`、`.mts` live 脚本）与默认测试的区别、隔离数据根用法、已知跳过表。

**E4 GitHub Actions CI。** 新增 `.github/workflows/ci.yml`：push 与 PR 到 `main` 触发；矩阵 `windows-latest` × Node `22.x`（engines 下限）与 `24.x`，可加 `ubuntu-latest` × `22.x`；步骤 `npm ci` → `npm run typecheck` → `npm test` → `npm run build`。不注入任何密钥、不访问真实 Provider 或外部资讯源；需联网的测试不得进入默认 glob。确认 `@napi-rs/canvas` 等原生依赖在 runner 上可安装。验收以**远端实际 CI 运行结果**为准（主线程推送后读取 Actions 结果）；网络或认证阻塞时如实标“阻塞待验证”。
