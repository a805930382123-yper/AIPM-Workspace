## 最小变更

1. 清理仍用现48单元/32KiB协议和原批界；原35批逐项不变，之后19批仍按原服务继续。默认不改cleanup提示/schema。新revision6仅重做尚未执行的索引/写作组织，显式开始时验证同Raw/原件/R1/provider后归档旧rev5检查点并复用有效前缀，不重发成功调用、不清零累计计数。旧版本GET/草稿仍原路径可读；不得在启动或GET自动迁移/调用。
2. 索引键使用已清理的唯一topic标签，不再为每个句子派生key。索引每批仍16标签、32KiB，提供完整实质原单元小样及已有相关主题。要求以适合知识页的完整议题归类，同一议题细分材料放在正文中组织；不强制每章一篇，不用标题合并掩盖不同主体/口径。章节信息可作为导航上下文，不新增图谱/分类平台。50最终主题上限不提高。
3. 写作输入采用证据包：同最终主题、页、origin和section中连续的完整保留原单元合包；原文字严格保留顺序和内容，不跨独立样本伪接句、不先截断或自由摘要。每包稳定ID，成员unitId/页/来源映射由本地保存。每请求仍受24KiB、48证据包和最多4主题约束；超包按原单元边界拆，单个原单元过大显式失败，不静默省略。
4. 写作保持现事实段落+coverage合同，coverage对证据包负责，服务端展开为原成员完整归属和引用。included/duplicate段落保所有被覆盖实质信息；metadata/promotion不能吞有内容的混合包。输出仍AI整理，不变成Raw逐字事实。表格、推断、待核问题沿既有路径，全部原页证据可展开。原整体编辑/选择/确认/版本门禁复用，不逐片审批。
5. 不增加通用任务层/自动重试。当前cleanup120秒、其余阶段60秒及取消保持。本次三次超时均未收HTTP头，现证据不能区分生成尾延迟和连接/代理因素；不得伪称根因已解。通过减少索引键和写作coverage槽降低重复序列化/输出量，离线比较完整wire与槽数。后续真实工具可记脱敏错误name/code和是否收到头，禁止header/key日志；不是额外诊断请求。
