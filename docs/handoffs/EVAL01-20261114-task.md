# EVAL01 AI 质量评估基线 任务卡

属于 [AI 自动化路线图](../batches/AUTO-ROADMAP-20261114.md) 阶段 0，开发侧工具，**不进入产品运行时**。目标：把过去靠人工 gold 打分的质量判断，变成可重复运行的评估集与评分器——默认离线回放（零费用、可进 CI），需要时显式切换真实 Provider 跑一次并记账。之后改提示词、换模型或调整自动化，都能先看评估结果再决定。

## 评分与模式

需求明确度 1（评分维度需规划者细化）/ 模块耦合 1（只读调用既有 LLM 服务链与校验器）/ 变更风险 0（不改产品、不写正式数据）/ 历史失败 1（知识整理真实质量多次未过，评估口径曾有争议）= **3，A 标准**：Astra 规划，Sol High 先审计划，Terra High 施工，不同实例 Sol High 独立验收。

依赖 ENG01 PASS。可与 RUN01 并行（文件所有权不重叠）；不阻塞 PIPE01。

## 必做

**V1 用例格式。** `evals/cases/<chain>/<caseId>/`：
- `case.json`：链路名、输入（Raw 正文文件引用、模式 standard/deep、附加参数）、`license`（`synthetic` / `own` / `public-excerpt` / `copyright-local`）、来源说明、创建日期。
- `gold.json`：确定性检查——必须出现的事实（含可接受同义表达或关键数值/单位）、禁止出现的断言（编造数字、把预测写成事实、把推断写成原文事实）、必须保留的待确认点、字段完整性要求。
- `recordings/<recordingId>.json`：录制的 Provider 请求摘要（不含密钥）与原始响应，用于回放。
- **仓库是公开仓库**：`copyright-local` 用例（基于真实研报/付费内容）只放 `evals/local/`（加入 `.gitignore`），提交的用例只能是 `synthetic`/`own`，或经确认可公开的短摘录。

**V2 运行器。** `npm run eval -- --chain <name> [--case <id>] [--mode replay|live] [--recording <id>]`：
- `replay`（默认）：用录制响应替代 Provider，经过**与产品完全相同**的解析、结构校验、证据映射与组装代码，零网络。
- `live`：必须显式 `--mode live`；使用当前产品配置的 Provider；开始前打印将发送的用例数与预计请求数；逐次记录请求数/token/未知用量；可用 `--record` 把响应保存为新录制。失败不自动重试。
- 输出 `evals/results/<时间戳>-<chain>.json`（gitignored）与终端/Markdown 摘要；支持 `--baseline <结果文件>` 对比，显示各指标升降。

**V3 确定性评分器。** 至少包括：结构/校验通过率；证据保真（引文在 Raw 原文中逐字存在、位置正确）；必含事实召回率；禁止断言命中数；事实/整理/推断/待确认分区是否混用；重复率（同一事实重复陈述）；空主题/仅标题主题数。每项给出用例级明细，便于定位。LLM 评审（judge）不做或默认关闭。

**V4 种子评估集。**
- `standard-extract`（Raw 标准整理）：≥6 个用例，取自既有**合成**材料（`docs/reports/WORK05-SIM-20261108/`、`docs/reports/WORK-CLOSED-20261109/`、AUTO-REAL 合成样例等），并补充 ≥2 个专门构造的陷阱用例（预测 vs 已发生、口径/样本条件、数字单位）。
- 若规划者判断可行，`deep-extract` 或 `news-relevance` 可先只建格式与 1–2 个示例；`news-relevance` 的完整用例由 PIPE01 补充。
- 历史真实 gold（如 PDF01 六页 gold、KB/LW 样例）若在本机存在，可整理为 `copyright-local` 用例放 `evals/local/`，不提交；本机缺失则如实记录，不补造。

**V5 基线与 CI。** 对种子集录制一次真实响应（live，记账，无上限但失败即停），生成首份基线报告 `docs/reports/EVAL01-20261114-baseline.md`（只含指标与用例级结论，不含受版权正文）。CI 增加 replay 模式评估步骤（仅已提交用例），指标低于基线阈值时失败；阈值由规划者冻结并写入 `evals/thresholds.json`。

## 验收项

- **EVAL01-01** replay 模式经过与产品同一套解析/校验/组装代码（验收者通过注入一个故意不合规的录制响应，确认评估报告给出与产品相同的拒绝原因）；零网络（断网或拦截下运行通过）。
- **EVAL01-02** 评分器正确性：每个评分器有正反例单测；人为修改录制响应（删掉一个必含事实、加入一个编造数字、引文改一个字）时对应指标准确变化。
- **EVAL01-03** 种子集满足 V4 数量与 license 要求；提交内容无 `copyright-local` 材料、无密钥（扫描通过）。
- **EVAL01-04** live 模式：必须显式开启；实际真实运行一次，报告请求数/token/未知用量；失败不重试；录制可被 replay 复现同一评分。
- **EVAL01-05** 基线报告存在且与 `evals/results` 实际结果一致；`--baseline` 对比可用；CI replay 步骤在远端实际运行通过。
- **EVAL01-06** `npm run check` 通过；产品行为无变化（若导出内部函数，相关产品测试通过）。

#### 1. 链路边界和最小接口

本批仅实现 `standard-extract`，输入为独立合成 Raw，无 Wiki 上下文；不做可选 deep/news 示例，也不整理历史版权正文。评估对象是标准提取与规划组装出的 `ExtractOutcome`，不声称覆盖后续 Wiki 检索、maintenance 提案、DraftStore 落盘或正式确认。

必须直接调用 `services/llm/knowledge-extraction.ts` 已公开的 `runKnowledgePipeline(KnowledgeRunInput)`，经其 `validateKnowledgeCheckpoint`、parse/strict schema、atom/locator 映射、规划覆盖检查及最终组装；不能使用旧 `LLMService.wikiExtract` 代替当前链，也不能在脚本内复制解析/组装器。`provider.complete` 是唯一替换点，replay 注入顺序录制队列，live 注入 `OpenAiCompatibleProvider` 的记账包装。checkpoint 使用真实 rulesVersion、分块、Raw SHA 和全新空 completedChunks/plan；每次调用前递增 attempts。可使用现有 CheckpointStore 的 TEMP 根或纯内存回调，不初始化生产 Store。beforePlanning 必须以内存回调保存 maintenance:{version:1,context:[]}，使规划请求携带 wikiContext:[]，与产品空库路径一致；不读正式 Wiki。当前需要的入口/类型已导出，**预期产品导出改动为零**；若施工发现确有缺口，先报告具体函数与理由给主线程，只可批准无行为改变的 export，不抽公共框架。

`case.json` 固定 schemaVersion=1、id、chain、license、source（历史合成文件及 eventId 或新编说明）、createdAt、input（bodyFile、稳定 rawId/title/sourceType/sourceName/tags、mode=standard）。路径只解析本用例正文，禁止绝对路径或逃出用例目录；公开集本批只 synthetic/own。gold 与 body 施工前定稿，独验 live 前记录 SHA，live 后不得改 gold 迎合结果。

`gold.json` 固定 schemaVersion=1：requiredFacts、requiredQuestions、forbiddenAssertions、partitionRules、requiredFields。事实/问题条目含稳定 id 和 variants；每个 variant 是必须同时出现在同一对应条目中的字符串列表，variants 之间为 OR。可包含主体、时点、条件、数字与单位，避免仅找数字便算召回；只允许 NFKC/空白规范化，不模糊改数字、单位、否定。forbiddenAssertions 使用同样的有范围匹配器；分区明确限定 source_facts、open_questions、ai_organized、ai_inferences、templateFields.aiContent，不能把整个 JSON 序列化后全局搜词充作评分。标题/摘要可扫禁止断言，但不算事实召回。模板字段中的 AI 文本必须单独纳入禁止断言/分区检测。

录制文件含 schemaVersion、origin=synthetic|live、case/body/gold/rules 指纹、Provider 非敏感 name/model、按序 calls。每次保留 stage、请求内容摘要及 requestHash（system/user/purpose/structuredOutput；不含 signal、易变 timeout、凭据）、完整 `LlmCompletion`（原 text、finishReason、bytes、structuredOutputApplied、usage）。不得存完整配置/headers/密钥；live 响应写盘前调用现有秘密扫描，命中则只记安全错误。严格检查请求 hash、条数及顺序，缺失/多余录制均失败，不能按阶段猜配或回退联网。录制格式只验证 completion 外壳，不预先解析/拒绝其模型 text；故意非法 JSON、未知 atom 等必须送入产品 parser 并得到同码拒绝，不能被录制格式校验抢先拦下。规则变化导致不兼容应报告并要求显式重录，不能悄悄更新录制。人工构造录制只能标 synthetic，不能标为 live。

结果 JSON 含 schemaVersion/runId/mode/chain、时间、代码 HEAD 与本批关键文件 SHA、用例/gold/录制/rules/阈值指纹、每用例 status/错误码/指标分子分母/命中明细、汇总、调用账本。`--baseline` 对相同 chain、用例集合与评分 schema 比较，缺项或不兼容明确失败；不得把缺失项当零。Markdown 摘要与 JSON 同源生成。CLI 默认 replay；未知 mode/chain/case/recording 等参数在外发前失败。结果与本地材料 gitignore，基线报告保留可复核指标及指纹。

#### 2. 评分定义及施工前冻结门槛

以下门槛写入 `evals/thresholds.json`，schemaVersion=1，不能由 live 成绩自动下调。阈值表示本种子基线的质量要求，不代表全面语义正确。分母为零显示 N/A，不能伪造 100%；预期成功种子被产品拒绝时结构失败，召回记 0，其余不可计算项 N/A，整用例失败，不能从汇总删除。

| 指标 | 计算与明细 | 冻结门槛 |
|---|---|---|
| 结构/校验 | 产品链实际完成数/应完成数；保留产品 LlmError.code 和安全详情 | 8/8，100% |
| 证据保真 | 每条 source_evidence 的 rawId、UTF-16 start/end、body.slice(start,end)===quote，引用 ID 可解析；列失败位置 | 100%，无悬空引用 |
| 必含事实召回 | 每个 gold 事实在 source_facts 单条中匹配计一次；每例及全体 micro 命中数/总数 | 每例≥0.80，全体≥0.90 |
| 待确认保留 | requiredQuestions 在 open_questions 中匹配 | 100% |
| 禁止断言 | 按 gold 指定 scope 逐条计命中，给断言 id 与字段位置 | 0 |
| 分区混用 | partitionRules 指定必须/不得出现分区；预测原句保留“预计/尚未”可为来源事实，不机械禁止预测进入 source_facts；ambiguous 原句保留事实且有待确认标记合法 | 0 违规 |
| 重复率 | source_facts 规范化文本相同且证据原文区间相同才视为重复；重复条目数/事实条目数，跨页也检查；不同主体/位置不能只凭相同数字合并 | 0 |
| 空/仅标题主题 | 无非空 source_facts 或缺非空标题；按实际 outcome，不以模板字段填充掩盖空事实 | 0 |

重复率仅测确定性的重复陈述，不冒称语义近义去重。分区检测仅覆盖 gold 明示的风险，不启用 LLM judge。冻结基础字段检查包括 document.title/main_topic/summary/source_level、pages 的 title/type/category/source_facts/source_evidence/open_questions/ai_organized/ai_inferences，符合当前产品契约；可选 templateFields 缺省不扣分，出现时检查其实际引用。

结构不合规与语义评分分开：故意删规划必需 ID 会触发产品覆盖拒绝，应报告结构失败而非伪造完整产物。评分器单测使用合法结果的受控副本，验证删除事实、添加编造断言、改引文一个字各自降低对应指标；另做录制响应变异，验证删除提取 atom 后召回下降、在合法 template text 加编造数字后禁止数上升，以及未知 atom/非法 JSON 的产品拒绝。同一失败可以影响多个指标，但报告不能混淆拒绝与评分。

每例 gold 至少2条必含事实和1条禁止断言；确有明示待确认的例必须 requiredQuestions，不凭想象添加问题。gold 应把当前原文同一 atom 的多项内容作为可匹配组合，不要求模型复述固定页标题。两个陷阱由施工先写正文和 gold，经 Sol 静态核验后冻结，不能根据 live 调整。对8例固定排序，不随机抽样；所有正文均应在现行分块规则下单 chunk，预计每例提取1+规划1=2次，共16次。实际由 chunkText 计算并在启动前打印，有差异先核对材料，不能隐藏额外调用。

#### 4. live 最小计划、费用与基线

施工只运行离线 synthetic 录制与 fake 单测。独验完成离线安全/正确性检查并确认停写后，仅进行一次8例顺序 live 会话；不并发、不自动重试、不重新挑样。使用当前产品 `loadLlmConfig` 与 `OpenAiCompatibleProvider`，沿用 `FMCG_LLM_CONFIG_FILE` 或产品同一默认路径规则和现有 env 优先级。配置只在显式 live 分支内部读取，不打印/复制凭据，不写配置，不发送额外连通性探针。代理沿现有 Node 环境代理启动方式，不改全局代理。replay 分支不加载真实配置、不构造真实 Provider；独验拦截 fetch/http/https/net 等外发路径核对零调用，不能仅以“没设密钥”证明零网。

`--record` 保存此次真实响应为独立 recordingId；每次实际 complete 调用前持久化 attempted 账本，返回后写 success/failed、耗时、已知 prompt/completion tokens、unknownUsage。失败时读取 LlmError.details.usage 中已有的部分 token，并标缺失部分未知；失败或部分 usage 不得按0 token/0费用报告；没有价格来源不估造金额。记录请求级 usage，不使用 pipeline outcome 中固定为0的占位 usage。服务端可能已计费但网络失败时明确未知，不取消这条请求。记账写入失败时停止进一步外发。

首个 Provider、解析、校验或用例质量门槛失败即停止后续 live，保留此前账本及已得录制，未执行用例标 NOT_RUN。任何重跑需先向主线程报告原因，不能通过换模型、改配置/提示词/gold/门槛继续试到通过。本批无预设金额上限，但不代表无限试错。质量失败属于评估发现，分别报告评估工具工程是否通过及真实质量/本批未通过或缺证；不因失败而修改产品。本批不得用 synthetic 完整基线覆盖未完成的 live 基线。

一次8例成功后，将经过秘密扫描的合成正文对应 live 录制纳入公开用例，默认 CI 选择这组明确冻结的 recordingId，不以目录最新文件猜选。独验 replay 必须逐例复现同一指标、错误及命中（时间/运行ID/耗时不同可忽略）；保留 live 与 replay 结果文件指纹。在基线报告列每例数值、聚合、请求总数、已知/未知用量、原始结果 SHA、recordingId、代码版本，禁止含配置、受版权正文。CI 使用冻结阈值直接 gate，不在 CI live；显式 `--baseline` 对比另测升降与不兼容。

#### R1-A 评分语义 v2（不改变质量阈值）

现 `matches` 的整字段 exclude 会漏掉否定变体，也可能以字段里一处否定豁免另一处肯定造假。本次仅给 forbiddenAssertions 使用命中级局部排除；事实召回、问题召回、partitionRules 及其原指标语义保持。结果 `scoringSchemaVersion=2`，报告同时记录评分器SHA；录制外壳schema和原录制不改。旧v1结果与v2结果不能作为同版本 `--baseline` 直接比较；用同录制重评产生v2基线，原v1只作为历史失败与来源证据关联。

实现采用一个小型确定性局部匹配过程，不引入通用NLP、judge或完整语法框架：

1. 对每个 forbidden rule 的候选字段按原规则找出各次肯定断言的词项命中span；variant中的词项须同一分句，保留每次位置，不能找到第一个被否定匹配后就结束整个字段。按原规则的id/path输出一次违规即可，但详情列未豁免的span，排除详情另列依据。
2. 分句边界为句号/问号/感叹号/分号、逗号、换行（含中英文等价符号），以及明确转折/另起断言词“但/但是/然而/不过/而实际上/而实际/事实上/并且”。先按原文本划分边界再在片段内规范空白，保留原位置映射；不能先折叠换行而失去边界。边界规则只用于 forbidden 检查，不更改正文和产品输入。
3. 仅在同一分句、同一断言span前紧邻识别局部否定。对gold已有以“不证明”开头且其余断言匹配该variant的exclude，允许固定否定前缀“不证明/不能证明/不能据此证明/不能由此证明/无法证明/不足以证明”，及断言词项之间明确的“都/会/都会”和空白。不得将任意文字当作可跳过内容，不以大段 `.*` 跨另一否定/肯定谓语寻找配对。不能证明其归属时维持违规，由人工判断，不能默认豁免。
4. 其他字面exclude仍可使用，但只排除其覆盖的同一候选断言span，不再让整个字段内任一exclude豁免全字段；不能只见“不/未/不能”就忽略。不得以本次完整输出句子建立特判，不增改gold排除字符串。

必测对照：原文“不证明所有大范围请求失败”及本次“不能据此证明所有大范围请求都会失败”均不违规；“所有大范围请求都会失败”违规；“不能证明所有大范围请求失败。所有大范围请求都会失败”违规；换逗号/分号/换行或“但/并且”相连仍保留后一肯定违规；“不能证明小范围请求失败，所有大范围请求失败”违规；同句同字段先肯定后否定也不能擦除前者。加至少一条不同主题的同构rule验证不依赖“所有大范围请求”字面。原所有评分指标回归。独验检查前4份真实录制重评，确认只修正确排除，事实/证据/问题等指标不变化，原gold/body/录制SHA不变。
