## Persistence / recovery handoff

Checkpoint format version is `kb02-1`; one JSON checkpoint is stored at `state/extraction-checkpoints/<jobId>.json`. It contains the raw hash, rules version, non-secret provider cache identity/model, chunk descriptors, validated extraction chunks, optional complete knowledge plan, current stage, bounded outbound attempt ledger, optional draft ID, and an integrity digest over canonical checkpoint JSON. Only complete, schema-valid chunk results and a plan with exact full coverage are saved. Explicit resume reuses validated chunks and the same job ID; `{restart:true}` creates a new logical job. A failed/cancelled outbound call consumes an attempt before the call, and no automatic retry occurs. Corrupt records are rejected by both lookup and list paths. After draft creation, the job/checkpoint is reconciled to completed/done so restart/recovery does not publish a duplicate draft.
