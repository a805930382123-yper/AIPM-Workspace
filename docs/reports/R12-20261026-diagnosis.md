## 待 Astra 确认的最小方案

在提取草稿增加**显式人工引用标记**，把完整来源 fact unit 同时列入该页待确认问题；原 unit 的 kind/factKind/text/memberIds/records/evidence/basisDigest 和原 source_facts 全部保留，不拆复合句、不改原模型分类。问题正文用“人工标记待确认：”加完整 unit.text，使人工决定与模型原分类可辨。

建议持久化为 `DraftRecord.humanQuestionUnitIds?: string[]`，只记录已知 fact unit ID 的集合，缺省等同空。它不进入不可变来源目录，而由 candidateContent 现有完整候选绑定纳入内容摘要。严格读盘校验须验证数组、唯一性、已知 fact ID、与 humanReview 存在关系；普通 PATCH 不可写入。独立窄 POST `/api/drafts/:draftId/review/questions` 接收 baseRevision、unitIds、marked:boolean，仅 pending_confirmation 且来源有效时接受。真实已确认旧稿继续拒绝编辑，不迁移/重写历史。

此动作按实际变化失效全部逐页审批，重算 open_questions 与未被用户改写的 Source 预览并增加 revision；重复同标记幂等。撤销仅去掉人工引用，保留原有模型问题/ambiguous 问题；移页/合并后标记跟随完整 unit 所属页，未解决池仍阻断写入。来源事实、ID 和原始问题不增删。若存在同文本的原模型问题，不必另造新原问题 ID；人工标记是明确的引用关系，不伪装成新模型输出。

UI 在来源事实 unit 旁增加“同时列入待确认问题（人工标记）”复选操作，显示当前标记并提供撤销；忙碌/未保存/已确认时禁用。实际问题分栏、正式 Markdown 继续使用现有渲染，不增加模型请求或通用语义判断框架。
