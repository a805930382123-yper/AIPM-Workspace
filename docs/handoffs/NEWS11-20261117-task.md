# NEWS11 手动检查更新与失败来源补抓

基线HEAD `ddabd10`，以施工交接完整SHA和文件指纹为准。用户授权第一轮；按coordination/agent-router评分0/2/1/0=3 A标准：范围清晰，跨采集/状态/API/UI/PIPE01耦合2，增量保留内容且不迁移Raw风险1，无同核心修后复发。Astra规划、Sol先审、Terra施工、不同实例Sol独验。重大完整性风险未成立：冻结为保留旧条目、队列内原子合并、零新增模型调用，不引入覆盖归档或迁移。

## 冻结行为

1. 两栏今日视图提供“检查更新”：读取该栏所有已启用来源；快消另有“仅补抓失败来源”，只请求本期上次失败或部分失败的来源，成功健康来源零请求。两入口都手动触发，不增加定时器或自动重试；历史期刊无入口。检查不触发AI分析或预筛，providerFactory调用数为0，保留旧项已有analysis。
2. 所有手动操作保留当前已收录条目的id、日期、正文、analysis及顺序；新条目仅填空位，最多5条，快消每源2、日期窗、中国优先与URL/标题/PDF去重保持，已满不替换。AI新增按AIHOT当前原顺序取空位，不引入关键词筛选/日期窗/历史过滤；原自动生成的AIHOT选择语义不改。满额检查仍更新来源诊断，明确“已检查，本期已满5条，新内容未加入”，不伪称源无新内容。检查更新不是重新生成当天期刊或滚动替换。本条是保持Raw引用与已分析内容稳定的最小增量策略。
3. 补抓partial成功也保留已有好条目，用现有成功URL/标题/PDF排除集合避免重复详情；同标题前候选正文失败不能排掉后继合格候选。健康但empty/全重复/正文不合格的来源不算网络失败，不自动纳入“失败来源”；其可经“检查更新”再检查。无可补来源时零网络并显示无失败来源。
4. 运行中/失败/中断保留原items可读；最近精选按所有保留今日条目占用名额与去重，不因running重复补到超5。整栏status仍可表示本次尝试失败，有保留内容时文案明确“本次检查失败，保留上次内容”。无新增只用于完成了有效检查且未找到新增，不掩盖来源失败、重复排除或正文不合格。保存已保留条目在检查运行中/失败时仍可用（原期刊date/id，既有可读已收录内容）；不得放开尚未收录候选保存。

## 最小接口与并发

- 新增 `POST /api/news/today/check`，body建议 `{section,mode:'all'|'failed',attempt}`，mode failed仅fmcg，attempt为当前版本（首次无栏用0）。复用news-api本机Origin/JSON门禁、严格字段校验；返回既有today视图。旧retry接口兼容，但快消重试改走保留内容的失败补抓，不能再清空已有条目。旧无来源失败/首次初始化按所有已启用来源抓取，明确原因。
- 服务提供check(section,mode,attempt)，复用SerialQueue、active和launched Promise；启动前版本比较，并发重复请求返回409或复用同一任务，必须零重复抓取。不同栏目可独立运行；最终写入只合并目标栏，不覆盖另一栏。任务绑定启动时上海日期，跨午夜完成不得写入新一天。
- readSources第三参数保留exclusions兼容，可扩可选sourceIds（或追加可选options），逐层传到现有源适配器，实际跳过未选源而非抓完后过滤。sourceIds只可来自服务端已启用源表，用户不能传URL或启用CCFA。旧两/三参依赖注入仍可运行。
- `ensure()`仍复用当日缓存；`ensure(true)`继续等待该日两栏已存在launched Promise（包括手动检查），不新触发分析或重复抓取。PIPE01现有stageEdition/Raw共享服务不重建，不将手动检查接入pipeline预筛。所有真实来源HTTP仍走fetchNewsSource，保留AsyncLocalStorage计数归属：谁创建抓取谁的上下文，等待者不重计来源或模型费用。
- pending写盘重试必须携带合并后条目/诊断，不能回退成清空旧条目；进程重启running投影interrupted但保留内容。沿用原子JSON写入，无额外历史事件存储框架。

## 来源级诊断

SourceHealth增加可选稳定sourceId与最后尝试诊断；保留旧status字段兼容。最小字段为开始/完成时间、elapsedMs、lastSuccessAt、outcome/计数，以及首个安全error `{type,stage,message}`。type至少timeout/network/tls/http/parse/unknown，stage至少list/detail/pdf/parse；失败阶段按实际抛错边界，不凭总catch猜测。HTTP状态码可记录，禁止原响应正文/凭证/任意异常对象直出。

计数至少候选、合格、重复、正文不合格、请求失败，能表达“部分成功＋部分失败”。无新增/去重/正文不合格不是同一种错误；质量拒绝不算网络故障。lastSuccessAt定义为最近一次来源请求/解析成功完成（可以有效空结果），并明确标签“最近读取成功”；partial或全失败不推进，缺历史值显示未记录而非现在。允许保留首个安全错误和聚合计数，不建全量日志。没有真实阶段证据的旧记录显示未记录。

旧无sourceId记录按固定已知sourceName精确映射，不模糊猜测；未知名字保留展示、不发请求，提示无法定位旧来源，可用全量检查恢复已知来源诊断。旧failed/error提示可作为补抓已知源依据；只有无错误的ok不冒充失败。更新源的最后尝试状态替换旧状态，未尝试源完全保留。

## 验收门禁

- N11-01：两栏检查可用；快消仅失败/partial请求计数精确，成功来源零请求；空失败集零请求。旧source映射/未知安全处理、列表失败/详情失败/PDF超时/解析失败、质量拒绝/重复/有效无新增分别有准确诊断与时间；partial含好条目且可再补抓。
- N11-02：旧条目正文/id/date/analysis与Raw映射在运行中、全失败、部分成功、重启中断后保持；成功补位≤5/每源2、跨栏目合并不覆盖，满额明确不替换。历史/近期去重及原date保存、运行中保存、相同Raw幂等通过；不得为此复制新Raw。
- N11-03：重复点击/陈旧attempt/并发ensure(true)只一轮来源请求；等待不提前返回；手动providerFactory零调用；PIPE01来源计数和现有预筛计费上下文回归。不同栏目同时完成、跨午夜、写盘失败后重试不丢条目。
