# REVIEW01 每周工作回顾自动草稿与归档 任务卡

属于 [阶段 2 自动化路线图](../batches/AUTO-STAGE2-ROADMAP-20261120.md) 第三批。目标：在完全保留现有只读「周期回顾」（LIFEOS L6）的基础上，每周定时汇总全工作台事实快照并可选生成一份结构化中文周报草稿，支持审阅、人工编辑、归档与导出 Markdown，同时将周报总结纳入离线回放评估集。

## 评分与模式

需求明确度 1（周报结构、快照来源与人审边界已冻结）/ 模块耦合 2（调度器 `weekly` 计划、`periodReview`、工作事项、自动化账本、Provider 结构化输出、`PeriodReview` UI、评估回放）/ 变更风险 1（只写 `state/automation/weekly-reviews/`，不碰正式 Wiki/Raw/Prompt；但涉及将工作台聚合信息发往外部 Provider，须严格排除受限会议与 Raw 正文）/ 历史失败 0 = **4，A 标准（Sol High 先审计划）**：Astra Medium 规划，Sol High 先审计划，Terra High 施工，不同实例 Sol High 独立验收。（规划者若评估外发隐私边界需更高独立性，可直接定 B 并记录理由。）

依赖：KBMAINT01 PASS（复用 `weekly` 计划与知识库巡检统计）；若 WORKAUTO01 已通过，周报快照可附带活动提醒数，未通过不阻塞本批。

## 已冻结的产品决定

1. **只读周期回顾原貌保留**：`GET /api/home/review` 及现有按任意日期范围现算的只读查询功能 100% 保持原契约与零持久化行为。自动周报作为独立的持久化草稿档案并列呈现。
2. **先存确定性事实快照，再可选 AI 起草**：即使未配置 Provider、关闭 AI 总结开关或模型调用失败，确定性事实快照依然完整落盘且可读可导出，绝不因模型失败丢周报数据。
3. **严格的最小外发隐私边界**：发给 Provider 的输入**仅限本周确定性快照中的标题、状态、日期、计数与简短统计摘要**——**严禁**携带 Raw 正文、会议纪要正文、受限会议标题（`Restricted` 或 `meeting_local_only` 标定项按来源策略隔离/脱敏）或客户沟通详细正文。
4. **草稿归档不入正式 Wiki**：周报草稿保存在 `state/automation/weekly-reviews/<weekKey>.json`（`weekKey` 如 `2026-W47`），用户可编辑、标记“已审阅归档”、复制或导出 `.md`；不自动创建 Raw 或正式 Wiki 页。

## 必做

**RV1 全工作台自然周快照聚合（`services/automation/weekly-review-snapshot.ts`，0 模型调用）。**
- 周期定义：默认上一完整上海自然周（周一 `00:00` 含至下周一 `00:00` 不含，ISO 周标识 `YYYY-Www`）；手动触发时默认生成“上一完整自然周”，也允许显式指定一个已结束或当前自然周（如本周截至当前，明确标 `partialWeek: true`）。
- 聚合来源（各来源独立 `status: 'ok' | 'error'`，读取失败单列不冒充 0）：
  1. **知识新增与反馈**：复用既有 `periodReview()` 的 Wiki 新增、Prompt 反馈统计与当前待处理快照（仅保留非受限标题/ID/日期/状态）。
  2. **工作事项进展**：统计本周新建事项、本周关闭/解决事项（含解决日期与类型）、当前到期/未结事项列表（仅 ID/标题/类型/状态/跟进日期，**不含**反馈正文与沟通记录）。
  3. **知识库健康与自动化运行**：本周资讯抓取与用户确认入库数、最新 `wiki.lint` 总问题/本周净增减、本周 `wiki.inspect` 待核发现数、本周自动化总运行次数/失败次数/总模型请求与 token 用量（未知用量单列）。
- 对每个进入快照的条目给出稳定引用键（如 `wiki:<id>`、`work:<id>`、`prompt:<id>`、`run:<id>`），供下一步 AI 总结引用校验。

**RV2 定时任务 `review.weekly` 与结构化 AI 周报草稿（`services/automation/tasks/weekly-review.ts`、`weekly-review-store.ts`）。**
- 在调度器注册 `review.weekly`（显示名：`每周工作回顾草稿`），默认 `{ kind: 'weekly', weekday: 1, time: '09:00', timezone: 'Asia/Shanghai' }`、`allowsCatchUp: true`、`mayCallModel: true`，默认启用。
- 存储与幂等：按 `weekKey` 存于 `state/automation/weekly-reviews/<weekKey>.json`（含 `weekKey`、`period`、`revision`、`status`: `draft` | `reviewed`、`aiStatus`: `ready` | `facts_only` | `ai_failed`、`snapshot`、`draft`、`userMarkdown`、`generatedAt`、`updatedAt`、`reviewedAt`、`usage`）。
  - 定时或补跑触发时，若同 `weekKey` 已存在且已有人工编辑（`userMarkdown` 非空）或已归档（`reviewed`），**不得覆盖**，步骤记录“本周回顾已存在且有人审/编辑，跳过覆盖”并正常结束。
  - 用户可在 UI 显式点击「重新生成草稿」，基于最新快照刷新并递增 `revision`（若已有人工编辑须弹确认提示）。
- AI 总结（受独立设置开关 `aiSummaryEnabled` 控制，默认开启；关闭时 0 模型调用，记 `facts_only`）：
  - 仅发送脱敏后的本周快照，单次结构化 JSON 调用（严格 schema + `assertNoKnownSecret` + 计入运行账本 `usage`）。
  - 输出结构：
    - `executiveSummary`（≤300 字总体概述，标注 AI 整理）；
    - `highlights`（数组，每条含 `text`、`refs`: 必须是快照中真实存在的引用键，至少 1 条引用；快照无新增事实时允许空数组，禁止编造）；
    - `risksAndBlockers`（数组，含 `text`、`refs`：基于到期事项、失败运行、新增 Lint/检查发现）；
    - `nextWeekFocus`（数组，含 `text`、`reason`：明确标记为“AI 建议，待确认”）；
    - `openQuestions`（数组，字符串：数据缺口或待确认问题）。
  - 严格后校验：所有 `refs` 必须存在于当次快照索引中；任一引用伪造、越界、含已知密钥或 schema 不合法即拒绝整份 AI 输出，保留完整事实快照并将 `aiStatus` 标为 `ai_failed`（带明确错误提示，绝不落盘幻觉文本）。
  - 空周保护：当本周所有业务维度均为 0 变更时，允许短路为 `facts_only`（或明确空周提示），不强迫模型硬编进展。

**RV3 API（`server/automation-api.ts`）。**
- `GET /api/automation/weekly-reviews`：按周倒序列出已有周报摘要、设置（`aiSummaryEnabled`）与读取 `issues`。
- `GET /api/automation/weekly-reviews/:weekKey`：读取单份周报完整快照、AI 草稿与人工编辑内容。
- `PATCH /api/automation/weekly-reviews/:weekKey`：保存人工编辑正文（`userMarkdown`）或切换归档状态（`draft` / `reviewed`），强制 `baseRevision` 乐观锁防并发覆盖。
- `POST /api/automation/weekly-reviews/:weekKey/regenerate`：显式重新拉取快照并重跑草稿生成（带 `baseRevision` 与 `overwriteEdited` 确认标记）。
- `GET /api/automation/weekly-reviews/:weekKey/export`：导出规范 Markdown 文件（清晰分区：本周事实快照 / AI 整理与建议 / 人工审阅备注）。
- `PATCH /api/automation/weekly-reviews/settings`：开关 `aiSummaryEnabled`（带 `revision`）。

**RV4 UI（`app/components/PeriodReview.tsx`、`app/pages/AutomationPage.tsx`）。**
- 在既有首页「周期回顾」视图中提供清晰的双视图切换：
  - **实时周期查询**（原有 LIFEOS L6 只读体验与测试契约完全不变）；
  - **自动周报草稿**（左侧/顶部按周切换列表，展示 `facts_only` / `draft` / `reviewed` / `ai_failed` 标签；右侧清晰分栏展示“确定性事实快照”“AI 周报草稿（带来源跳转）”“人工审阅与编辑区”，支持保存、标记已审阅归档、导出 `.md`、重新生成）。
- 自动化页运行详情中的 `review.weekly` 记录提供直达对应周报的按钮。

**RV5 质量评估基线接入（衔接 EVAL01）。**
- 在 `evals/cases/weekly-review/` 新增 ≥4 个合成回放用例（正常活跃周、多风险/逾期周、含受限来源过滤周、极少/零活动空周）及确定性评分器：
  - 结构与严格校验通过率；
  - `refs` 真实存在率（100% 合法引用，0 编造 ID）；
  - 必含事实召回率与禁止编造断言命中数（0 命中）；
  - 事实与建议分区清晰度。
- 更新 `evals/thresholds.json` 与 `.github/workflows/ci.yml`，让 CI 自动跑 `weekly-review` 离线回放。

**RV6 文档。** `docs/architecture.md` 新增 REVIEW01 小节；`README.md` 补充每周自动回顾草稿的生成时机、数据范围、编辑导出与隐私边界。

## 排除

- 不自动将周报写入正式 Wiki、Raw 或 Prompt Library。
- 不修改现有 `GET /api/home/review` 只读接口语义与返回结构。
- 不自动把周报发送到外部邮件/IM（属阶段 3 讨论范围）。
- 不修改工作区中其他未提交任务文件。

## 验收项

- **RV-01 自然周快照准确性与隔离**：单测验证上海时区自然周边界（含跨月/跨年周）、各来源错误独立降级不冒充 0；受限会议正文、Raw 正文、工作事项沟通正文绝不出现在快照或发给 Provider 的 payload 中；原 `GET /api/home/review` 回归 100% 通过。
- **RV-02 幂等与结构校验**：定时运行不覆盖已人工编辑或已归档的同周周报；AI 返回伪造引用 ID、缺失字段、密钥或非法 JSON 时整份拒绝，完整保留事实快照并标 `ai_failed`；关闭 `aiSummaryEnabled` 或无 Provider 时 0 调用输出 `facts_only`；编辑保存校验 `baseRevision` 409 冲突；`backup_workspace` 导出/恢复通过。
- **RV-03 正式资产不变量**：整个 `review.weekly` 定时与手动重生成流程结束后，正式 `wiki/`、`raw/`、`prompts/` 文件 SHA 不变，正式写入事务 0；自动化上下文调用正式写入被 `403` 拒绝。
- **RV-04 真实 Provider 端到端与评估回放（隔离 TEMP 数据根）**：用合成一周数据（含新增 Wiki、Prompt 反馈、客户/产品事项、Lint/资讯运行）触发真实 Provider 生成 1 份周报并如实记账请求数/token/未知用量，抽查全部 `highlights`/`risksAndBlockers` 引用与事实一致、无编造数字；`npm run eval -- --chain weekly-review --mode replay` 全部 ≥4 用例通过阈值（零网络）。
- **RV-05 真实浏览器 UI（1440px 与 390px）**：隔离生产构建中验证「周期回顾」双视图切换（原只读查询可用）、查看周报快照与 AI 草稿、人工编辑保存、409 冲突提示、标记已审阅归档、导出 Markdown 内容正确、从自动化页运行详情跳转周报；无水平溢出、控制台 0 报错、截图存证。
- **RV-06 全量回归与远程 CI**：`npm run check`、三链离线回放（`standard-extract` / `news-relevance` / `weekly-review`）及推送后 GitHub Actions Windows Node 22/24 CI 全部通过。

## 需用户决定（施工中遇到再问，不阻塞开工）

- 周报默认定时时间（本卡默认周一 `09:00` 总结上周一至周日；若偏好周五傍晚总结本周，可在界面随时改 `weekly` 计划）。
- 后续是否需要一键将已审阅周报“转为 Raw 导入”（本批先支持导出 Markdown，避免绕开 Raw 来源边界）。
