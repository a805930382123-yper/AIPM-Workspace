1. **本样本不缺少区域信息。** 原 106400 字 Raw 按历史生成器重建后 SHA256 为 `a60cad47549b175a9eedcde1cb1246ddbaba2891abdb492f00212a26aac513c7`，与原 Raw 记录和 checkpoint 一致。以当前 `buildKnowledgePlanningInput` 重建的 73721 UTF8 字节 JSON 与 seq180 实际 wire 输入逐字段完全相同；42 个 sourceContext 原文均逐字匹配。14 处边界陈述的上下文全部包含该区明确名称、2026 年 9 月、门店数／比例、区域独立说明，以及原边界句；每处窗口内的 `虚构区域NN` 主体标签恰为所属主体，没有其它区域主体标签。

3. **严格机械门禁不能证明该语义正确。** 原响应 schema 合法，55 unit／100 原 ID（79 fact + 21 question）恰好一次、split=0；当前 pipeline 接受它。内存 fake 仅返回原响应，一次规划调用即可从原 14 块 checkpoint 组装出同一错误页面。新 probe 比较了全部组装页面字段与历史 Draft：仅排除编辑器元数据、归一化 `source_evidence.occurrences`（组装输出为 1，存储草稿无此字段），其余一致。
4. **现协议能够表示主体保留的方案。** 测试单独提供一个按 fixture 真实主体分配边界 unit 的响应，仍由当前 pipeline 正常接受；全部 unit、原 ID、原事实／问题保留。这只是“可表达”正对照，绝不作为产品运行时纠正，也不证明真实模型会选择该方案。
5. **现有提示并非完全缺失规则。** `knowledge-extraction.ts:195` 已禁止因泛化待确认创建页面，`knowledge-planning.ts:71` 已要求依据 sourceContexts 保留主体／时间／条件／口径，且未知／未来等归入有事实支撑相关主题。实际重放的完整 system 与 seq180 原 system 完全相同。因此可证的是“上下文充分而这一次规划未遵守业务归属要求，机械门禁照常接受”，不能归因为“缺少禁令”、上下文被截断、旧同 unit 拆分复发，或断言某字段示例导致模型内部错误。

原响应把不同位置相同句子按通用内容集中，结果可观察；模型为何这样选择（注意力、提示优先级、示例影响等）均没有因果证据。本诊断未做真实模型对照实验，不把候选提示改动称为根治。

## 可审的最小修复候选

建议先限于**规划决策步骤及对照示例**，保持上下文、unit、schema、存储、Provider、预算、重试与 UI 契约不变。本次已证明信息充足，没有依据先扩大上下文窗口、增加自动主体解析器或跨模块数据机制。

相对于现有“不得泛化建页／归入相关主题”的总则，候选新增的是以下**可检查的决策顺序及冲突处理**，而非再重复一句禁令：

1. 分页之前，先对每个 unit 仅以其 sourceId 对应的精确位置与上下文识别原文明确的主体、时间、条件、口径；相同字面内容不能覆盖主体差异。该步骤只用于归属，不生成或改写事实文本，不新增输出字段。
2. 在该主体口径内判断“独立业务主题”的依据：有原文支持、可独立理解的业务定义／实体／流程／指标等才支持独立页；同段业务对象的未知、否定、未上线或未来建议通常是该对象的限制／待确认。先确定承载该对象的事实主题，再分配其边界句；不能只因含AI、负责人未知或相同措辞把各主体重新合成泛化主题。
3. 同主体同口径同主题跨 chunk 可合并；不同主体重复边界句仍须保留各自归属。一个主体可以有多个有独立依据的主题；不得将以上步骤解释为“一主体固定一页”或“只要含未来就不建页”。同原位置事实／问题在表示同一主题边界时应对应同一事实主题，但不改变其为独立 unit、可在原文支持不同业务断言时分别归属的现契约。
4. 在最终输出前，从各页反向检查所含 unit 的主体口径是否被标题和承载事实主题正确呈现；若一个候选页只因未知／未来类别聚合多个有不同主体的边界句，应重新规划其归属，保留全部 ID。只让模型在同一次响应内自检；产品不能自动搬移、删除、替模型补事实或发起重试。

建议用不含本长文区域编号的成对抽象示例解释上述区别，例如“岚河渠道在售门店30家，异常审批负责人未知”和“栖岸渠道在售门店50家，异常审批负责人未知”：两条未知各随其主体的门店事实主题；另用同一主体相同口径分散在两段的例子说明允许跨 chunk 合并。再给独立正例：原文确有告警机制定义、触发条件或流程时，AI主题可独立建页，不因出现未来／未知词被禁建。示例仅说明归属，不输出真实样例ID、固定页数、硬编码区域或对原文作新断言。

这是一项**有界但待实测的规划行为改进**。没有可靠、通用的程序语义识别器证据，本轮不提出字符串／位置距离猜主体的自动修正或“语义正确”伪校验。若真实原例仍同核心失败，应停下并交 Astra 升级诊断／重规划；不能继续靠增加禁令盲试。
