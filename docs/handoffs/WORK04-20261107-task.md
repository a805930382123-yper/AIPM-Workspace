## A 使用流程

- 用户在已完成分析的详情内主动点击「检查分析依据」。发送前展示目标轮次、原输入范围和原草稿，提示会把该轮当时实际发送的文本及其输出送给当前设置中的模型。模型可以和原分析相同。资料及正文按原快照展示，不换成当前 Raw、当前结论或其他轮次内容。
- 检查观察和结论与原文是否匹配，关注遗漏反例、统计口径、过强的推断、把未核内容写成事实。检查完成显示「模型复核」意见，可对照原输出及其依据。无问题时显示「模型未发现依据问题」，发现问题或证据不足时显示相应原因。请求失败或中断明确显示状态及原草稿；复核不代替用户确认。
- 每次显式操作最多触发一次额外请求。已完成可回看；失败或中断可显式重试并保留先前记录。读取、刷新及自动恢复不触发模型。复核意见只展示，不覆盖分析输出、不触发改稿、不代填阶段成果、不改已确认结论和未解问题。用户继续沿原入口带入、编辑、保存。

## A 数据与接口

- `POST /api/work-items/:id/analysis-runs/:runId/basis-review` 首次调用无业务参数。用户点击「重新检查」时提交 `{retryFromReviewId}`，其值为界面显示的最近一次失败或中断复核的 `reviewId`。服务端按 `itemId` 和 `runId` 读取同事项的已完成运行，拒绝未知、跨事项、未完成执行及客户端提交的替换正文。已完成的 v1 和 v2 分析均可复核，按原版本定位条目。旧记录未检查时 `basisReview` 缺省。
- 复用请求级 Provider 获取方式、已知密钥及安全错误清理。只发 `{input, output}`，其中 `input` 从目标轮快照还原实际发送视图，`output` 为该轮原输出。发送前从目标轮取得 `sourceRawIds`，旧 v1 从该轮 `input.sources` 取 ID，沿用 `raws.get` 和 `assertRawNotMeeting` 检查这些来源当前仍存在且可发送。缺失、受限或无法完成检查则拒绝；当前 Raw 仅供门禁判断，Provider 收到原快照，不加入后来保存的事项字段、其他轮次正文或当前 Raw 正文。已保存草稿及其当时依据可继续查看。
- 序列化请求数据最多 512 KiB，响应最多 128 KiB，最长 120 秒。超限、未配置或门禁拒绝不调用。复用分析执行的进程内占位方式，在首次异步读取前按目标轮次占位；已有占位的重复请求返回 409。占位内读取最新复核，无参数且已有记录则返回原状态，无新增发送。带 `retryFromReviewId` 仅在匹配最新的 `failed` 或 `interrupted` 记录时创建尝试，陈旧或状态不符返回 409，界面刷新显示最新结果。复核记录无法可信读取时拒绝启动并提示恢复，已有记录仍按故障处理。发送前原子保存独立 `reviewId` 后单次调用 `provider.complete`。重启后未结算记录显示中断，保留旧尝试，无自动重试。
- 以 `work-items/analysis-runs/<itemId>/reviews/<runId>/<reviewId>.json` 保存版本化复核记录，绑定事项、目标轮次、尝试序号、当前 Provider 名/模型、开始和结束时间、状态与结果或安全错误。状态为 `running | completed | failed | interrupted`，完成才有结果。`GET /api/work-items/:id/analysis-runs` 在相应 run 的可选 `basisReview` 返回最新一次状态及结果或失败原因，原运行文件及输出保持原样。沿用备份递归白名单；复核读取错误作为该轮复核不可用展示，保留原草稿可读。
- 返回 `checks`，逐项覆盖 `observations.<零基下标>`、v2 的 `roundSummary` 和非空 `themes.<零基下标>.conclusion`，另有 `scope` 检查重要反例、口径及事实与推断的界线。每目标恰有一项，最多 34 项。每项 `{target, decision:'supported'|'unsupported'|'uncertain', reason, evidence}`，`reason` 为 1–500 字的可核对理由，`evidence` 为 0–3 条 `{rawId, quote}`，须从本轮原文逐字摘取。对观察及标为有依据的主题结论，`supported` 须至少有一条证据。核查假设的表述与依据是否相符，复核意见不确立事实。遗漏、重复、越界、伪造证据、截断和非法响应保留失败。只在每项均为 `supported` 时显示「模型未发现依据问题」。
- `services/llm/knowledge-semantic-review.ts` 的证据审查和不确定态可作设计参考；它对应 Wiki 规划契约，不接入工作事项运行链。工作事项复用现有 Provider、schema 校验及原子文件能力。
