## 授权与边界

只做快消候选补位，以及资讯页两栏抓取时间、实际条数、不足原因展示；各最多 5 条。沿用 Worldpanel/NIQ 来源与正文质量门槛、365 日窗口、中国线索优先、历史 URL/标题去重。AIHOT selected/24h/limit=5、源顺序、格式校验、可选分析保持。每日缓存、失败重试、历史回退保持；不新增源、不增刷新按钮、不重建今日缓存、不写正式 workspace、不调用真实产品模型。

## 实现契约

1. 服务先读取既有一年内成功 research-v1 历史，形成规范化 URL 与标题排除集合，经 readSources 的可选第三参数传给快消适配器；两参旧注入仍可用。适配器在详情预算截断前排除历史、重复、过期/未来、不合主题和不允许地址。复用同一规范化规则，必要时将其放入一个共享 news 模块，避免循环导入。服务最终质量筛选、排序和去重保留。
2. 每源仅读取原有一个目录页；过滤及中国线索/日期排序后，按序尝试最多 **8 个详情页/源**（原为 4）；成功达到 **5 个独立合格条目/源**即停止。失败、无正文及本次重复不占成功名额。目录同一规范 URL 可提前去重；本期同标题仅在前条已取得合格正文后排除后继，前条正文失败不得挡住第二个 URL 的可读补位；最终服务继续跨源去重。NIQ PDF 尝试上限仍为 **2 次/源**，原大小/超时/页数限制不变。跳过历史不消耗详情预算。预算用尽如实少于 5，不无限翻页或循环请求。最终服务两源合并按现有排序最多 5；不能为补足放宽正文门槛。
3. SourceResult / NewsSection 增加可选诊断字段（具体名称施工选定后记交接），仅新生成记录保存。用实际计数/状态产生原因：历史或重复排除、合格候选不足、详情读取/正文提取失败、详情或 PDF 预算限制、来源失败；多个真实因素可并列。不能因少于 5 就猜测“源只发布了这些”，达到预算不能写“已遍历全部”。已返回 5 时无需不足说明。
4. AI 不改变选择算法；不足说明来自实际返回/格式校验/分析后数量。分析删减不能错误归因 AIHOT 返回不足。可用概括但准确的说明，如“本次来源或分析最终提供 N 条可展示内容”；有错误则继续展示原错误。
5. 展示实际用于渲染的 items.length（N/5），并显示抓取时间：既有 startedAt/checkedAt 表示本次抓取开始，finishedAt 表示完成，不能将其误称源发布时间或当前实时抓取时间。条目原 fetchedAt 可展示为抓取时间。时区上海，缺失/无效时间显示未记录，不生成现在时间。旧缓存没有诊断时显示“旧记录未记录具体不足原因”，不得重新抓取补诊断。
6. 回退时条数、抓取时间、不足原因均取回退 section，明确“显示 YYYY-MM-DD 的历史内容”；今日失败状态/错误及可用的本次尝试时间在当日状态上下文独立标识，不与历史内容时间混用。历史选期同样用历史 section。running 显示正在抓取，不能提前断言内容不足；无记录不假装抓取成功。保留原 legacyFmcg 历史区及保存 Raw 行为。
