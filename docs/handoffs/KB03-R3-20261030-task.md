## 原产物、覆盖与审核边界

R2 checkpoint中的scan/outline/note/qualityReport保留生成时快照，编辑不回写checkpoint。不新建审批框架。草稿保存最小编辑元数据（如noteEditedByUser和可写内容摘要绑定）；质量报告保留原始版本与原绑定内容摘要，编辑后UI/API显式标“历史模型报告，编辑后未复核”，不得继续展示当前确定性/模型passed。元数据由服务端派生，客户端不能自报“未编辑”或“有效报告”。无变化保存不必使审批失效，真实内容或覆盖变化必须清空全部HUMAN approvals且摘要变化；刷新不能恢复旧批准。

模型原文事实、引文和unit目录不可变；人工笔记文字/角色/事实选择单独存在。保留原始生成报告而不是删除旧警告洗成无问题。数值/单位等确定性错误仍提示，不能把用户编辑冒称模型已验证；人工编辑允许保存在待核对草稿，R1结构/有效引用/原文SHA这些硬边界不放宽，正式门禁仍关闭。禁止自动外发“复核”或自动纠正用户正文。

覆盖来自完整不可变fact/question目录及当前笔记引用/排除原因，服务端计算：已引用、明确排除、未覆盖，不能只显示模型旧included列表。删除章节/更改引用后丢失事实立即落入未覆盖，不静默消失；人工可明确排除并填理由，不能把未知ID声明排除。允许未覆盖草稿保存并突出待处理，不能标全部覆盖。事实归属可通过章节/叶项引用编辑；问题显示原文问题与人工补充的区别，可待确认但不伪造证据。

证据区显示引用fact文本及实际raw/evidence目录。点击引用在同页只读Raw正文定位/高亮对应start/end（多处相同引文按真实offset，不全文首匹配）；Raw缺失/变更显示错误并禁保存。页面保存/刷新后笔记、排除理由、问题与人工编辑标记读回一致。切换草稿/Raw或请求迟到不得覆盖当前正在编辑的另一记录；失败保留用户输入及可重试错误。

R2 validateSettlement当前将草稿笔记与checkpoint逐JSON比较。R3允许经过服务端编辑的合法草稿与原生成快照不同，需最小调整：未编辑草稿继续精确匹配，已编辑草稿核不可变来源/任务身份与服务端编辑元数据，不拿旧note覆盖新note、不重发模型。done草稿缺失/身份错配仍拒绝且不能另起账本；不得为了编辑放宽mode/rawSHA/jobId绑定。旧无笔记草稿不强制新元数据迁移。checkpoint仍是原生成证据，不是可编辑正文事实源。
