### 同目标归并及兼容

当前生成每 pageIndex 一项并拒绝重复目标，不能满足多个主题更新同页。改为最终成果可覆盖多个输入主题：增加明确的输入主题索引集合（如 pageIndexes），旧单 pageIndex 读取时视为单元素；持久数据/校验/渲染/选集/证据与提交映射一起适配，禁止只改提示词。每个本次输入主题应有明确覆盖或无需变更归属，禁止丢弃重复项。

生成协议要求相同真实 targetWikiId 只有一个完整候选，集合携带全部原主题证据、待核问题；依赖重映射到最终 changeId，去除归并导致的自依赖。模型违规返回重复目标应明确失败/显式修正，不自动选最后一项、拼接多份完整正文或无限重试。create 主题按实际语义独立，不按相似分数强合。已有旧 Draft/checkpoint/manifest 保持可读及原事务可恢复；仅未完成且确实协议不兼容者保留并明确显式重做，不能静默重发。无需批量迁移历史资料。

### 动作和目标调整

成果页支持新增、更新、补来源/无需变更及目标调整。目标必须是真实允许读取的 Wiki；服务端读取其正文、revision、来源并验证，不能信任客户端目标 ID 或旧目标候选。更新目标改变时，必须以新目标快照和本成果原始主题/证据重新准备完整候选，保留新目标人工内容和有效旧内容；旧目标无关来源与正文不能机械带入新目标。若采用模型重准备，使用现 Provider/checkpoint/计数与取消，界面明确展示准备中，失败保留已有成果不冒充成功。不得先正式写入。

update 改 create 要去除原目标绑定，候选仅保留本成果可追溯内容，不能复制旧页人工内容冒充本 Raw 事实；create 改 update 同上述新目标流程。link/noop 保持目标正文及元数据规则，新增来源不能冒充 noop。目标调整撞到另一成果时先归并再审核；已提交项不可重定向。任一动作/目标/正文变化清除旧确认，最终用户查看新实际差异后再确认。保留本次来源与目标原来源；对来源权限、事实引用和版本按现边界验证，不新建融合引擎。

### 结束和未选项

第一阶段提供显式结束本次选择/全部不采纳出口。未选不等于稍后处理，不自动制造待办；保存为任务历史的未采纳成果，不将草稿正文或证据删除。部分成功和失败分别记录，失败项仍可按原事务继续。无需变更表示完整准备成功且内容、来源都无新增，不得把检索失败、生成失败、空响应或未验证状态当成无变化；无需变更及全部不采纳均无需制造空 Wiki/Source 版本。已写入部分不能被“全部不采纳”抹掉结果。旧深度 Source-only 明确确认能力保持，不强制用它代替无变化出口。必要完成结果扩展现有记录即可，不预建父任务框架。
