## 已证根因与最小选择

UI mergePages、DraftStore.patch预检与applyMerge均拒绝非空templateFields。旧无字段merge不能覆盖R13当前候选。现字段仅一个aiContent（text≤4000、factIds≤256），将两页同字段文本强拼会混合humanEdited来源标签或超过上限；Concept/Process字段键不同，跨型塞入首目标槽会丢原语义。主线程已明确接受按原页保留字段组这一必要本地契约扩展。

**同型和跨型统一保全，不只实现同型。** 合并仍按现有首目标页pageId/type/category规则，不暗改类型；首目标的现有templateFields保持原编辑语义。其他原页的非空字段保存为独立原页字段组，明确原pageId/title/type、字段键/标签、人工说明、每个AI项及其humanEdited、原fact/evidence绑定。字段组不拼成一个AI项、不将Process步骤改名为Concept定义。再次合并时扁平保留原组，避免嵌套或同一组重复；首目标已有组照样保留。无字段旧合并路径兼容。

## 本地字段组契约与流转

1. 建议在DraftPage增加可选 `mergedTemplateFields` 原页组数组，使用单一固定version1本地结构；组含原pageId/title/type/rawId、fields及足以解释该组引用的原facts/evidence目录。可复用InputTemplateFields的字段/引用校验与渲染规则，但人工说明单独存在或纯问题页允许没有事实/证据，不为满足非空校验伪造内容。无需通用版本迁移框架。
2. 原页身份/类型、原事实、原证据及其ID/坐标由服务端merge从现有记录和不可变humanReview目录构造；PATCH不能新造组、换身份/引用、清空所有组或覆盖目录。UI可修改组内人工说明、AI文字及按现有字段方式明确删除内容；AI文字变更保留绑定并标humanEdited，原证据移归选择沿现有授权校验。删除必须是明确用户编辑，不成为合并前置条件。当前可编辑字段表单及新增组的编辑均纳入统一保存快照。
3. `deriveReviewPages`从全局humanReview单位目录重建当前页事实/证据，可能对碰撞ID生成稳定别名。合并保留unit/fact/question原ID、原文本、basisDigest不变，归属移到合并页；绑定不能依赖applyMerge旧临时rename。按unit身份与原Raw/位置/quote对齐；原页组若保持自身引用目录，必须验证目录来自当前归属units，并在展示/输出中清楚带原页命名空间；禁止同名不同位置证据串引。原templateFields人工证据及AI绑定也必须正确经过重建。
4. 合并本身及后续字段组文本/归属实质编辑使**全部页审批**失效；未全审或未解决时阻止任何正式写入。全内容digest覆盖新组；旧记录没有组仍可读，旧已确认/已完成manifest不追写。非法组/跨页引用/损坏盘记录须明确拒绝并保留原文件。
5. 审核预览和正式Wiki渲染均展示全部原页组、原类型栏目、人工/AI/人工修改标签与完整引用；Commit快照不能丢组。合并页后续旧Wiki update的输入快照、模型上下文、预览附录、审批/确认校验也必须携带组，不因只处理templateFields丢失；不改模型返回契约。共享渲染可复用有独立语义的现有函数，不另建渲染框架。
6. 容量沿现有单项4000字符/256 fact等校验，两个各自合法4000字AI项合并后仍为两个原页项，不截断/拼接规避。服务现有JSON入口3MiB保持；合并及roundtrip保存超现有有效载荷边界时明确原子拒绝，原草稿revision、字节、审批和Raw不变，不写出UI随后无法保存的半成品。无新任意小上限，不扩大存储/协议容量；确有边界实现取舍由施工交接说明。
