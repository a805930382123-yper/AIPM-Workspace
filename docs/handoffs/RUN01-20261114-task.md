# RUN01 后台常驻与自动化运行底座 任务卡

属于 [AI 自动化路线图](../batches/AUTO-ROADMAP-20261114.md) 阶段 0。目标：工作台可以在 Windows 上**后台常驻**运行，内置一个**可观察、可暂停、可追溯**的调度器，为 PIPE01 及后续自动任务提供统一的触发、记录与用量计量。本批不交付任何会调用模型或写业务数据的自动任务。

## 评分与模式

需求明确度 1（调度语义已在本卡冻结，个别展示细节可由规划者定）/ 模块耦合 2（启动方式、服务端装配、Provider 上下文、存储、UI、导航）/ 变更风险 2（后台进程与用户操作并发写同一数据根、本机服务安全边界、开机自启）/ 历史失败 0 = **5，B**：Astra 规划与独立验收，Sol High 施工。

依赖 ENG01 PASS（绿色基线与 CI）。

## 已冻结的产品决定

1. **常驻方式**：Windows“任务计划程序”在当前用户登录时启动生产模式进程；不安装 Windows 服务、不需要管理员权限。用户显式运行安装脚本才注册，卸载脚本完全移除。
2. **单进程**：生产模式由同一个 Node 进程提供 API 与已构建 UI，仅监听 127.0.0.1。开发模式 `npm run dev` 保持不变。
3. **单实例**：同一数据根同一时刻只允许一个服务进程（生产或开发）持有写锁，避免常驻服务与开发服务同时写同一 `workspace/`。
4. **调度只在进程运行时生效**；关机/休眠期间错过的触发，在进程启动后按任务配置最多补跑一次。
5. **不设预算上限**（用户决定），但每次运行必须记录用量；提供全局“暂停全部自动化”开关作为急停。
6. **导航**：新增侧栏入口“自动化”。首页显示一张自动化状态卡（最近 24 小时失败数、下一次运行）。

## 必做

**R1 生产启动模式。** 新增 `npm run start`：要求已 `npm run build`，以非 watch 方式运行 `server/index.ts`（可通过 tsx 直接运行），并由 Express 静态托管 `dist/`（SPA 回退到 `index.html`，`/api/*` 不回退）。端口沿用 `FMCG_PORT`（默认 4317），数据根沿用 `FMCG_DATA_DIR`。同源访问下既有 Host/Origin/writeToken 门禁继续生效且不被放宽；检查 `FMCG_UI_ORIGIN` 在同源模式下的处理。`npm run dev` 行为与端口不变。

**R2 Windows 常驻脚本。** `scripts/service/`：
- `install-autostart.ps1`：注册当前用户“登录时”触发的计划任务（默认名 `AIPM Workspace`，可参数化任务名、端口、数据根、是否走代理），动作是运行生产模式；设置失败后自动重启（间隔 1 分钟，最多 3 次）；打印将注册的完整配置并要求确认（`-Yes` 跳过）。
- `uninstall-autostart.ps1`、`status-autostart.ps1`（显示任务状态、进程 PID、端口、健康检查结果）。
- 代理：复用 `scripts/start_with_proxy.ps1` 的代理读取逻辑，不读 PAC、不改系统设置。
- 日志写入 `<数据根>/state/runtime-logs/`，按天滚动、保留 14 天，不记录密钥或业务正文。
- 脚本不得读取或打印 `.env.local` 内容；Provider 配置仍由服务端按既有 config-manager 读取。

**R3 单实例锁。** 服务启动时在数据根创建 `state/runtime/instance.lock`（PID、端口、模式、启动时间、主机名）。已有锁且对应进程存活 → 拒绝启动并给出明确提示（含占用进程的端口与模式）；进程已不存在 → 记录后接管。正常退出释放锁。开发模式同样取锁。

**R4 调度器与运行账本（`services/automation/`）。**
- 任务类型由代码注册（`type`、显示名、默认计划、是否允许补跑、是否可能调用模型、执行函数）。用户不能通过界面定义任意脚本。
- 计划持久化在 `state/automation/schedules.json`：每任务 `enabled`、计划（`daily` HH:mm 或 `interval` 分钟，时区固定 Asia/Shanghai）、`catchUp`（布尔）、revision。原子写入，复用既有 `services/storage` 写法与 revision 冲突处理。
- 运行记录 `state/automation/runs/<YYYY-MM>/<runId>.json`：`type`、`trigger`（schedule/manual/catch-up）、计划时刻、开始/结束、`status`（queued/running/succeeded/failed/cancelled/interrupted/skipped）、步骤列表（名称、状态、耗时、摘要、错误）、`usage`（requests、inputTokens、outputTokens、unknownUsageCount）、产物引用（rawIds/jobIds/draftIds 等，本批为空）。
- 同一任务类型不重叠运行；全局暂停时到点记录 `skipped`（原因 paused）而不是静默丢弃。
- 启动时把遗留的 `running` 记录标记为 `interrupted`，**不自动恢复执行**；按 `catchUp` 规则为错过的计划补跑至多一次。
- 取消：运行中任务通过 AbortSignal 取消，记录 `cancelled`。
- 保留策略：保留最近 90 天或 2000 条（取较多者），超出按月文件夹清理；`state/` 已在备份白名单内，验证备份/恢复仍通过。
- 自动任务不得调用正式 Wiki/Prompt 写入接口；在 automation 执行上下文中调用这些写入路径时服务端拒绝（加防御性检查与测试）。

**R5 用量计量。** 复用 `server/index.ts` 中按请求绑定 Provider 的 AsyncLocalStorage 机制，为自动化运行建立运行上下文：该运行内所有 Provider 调用计入运行记录 `usage`；Provider 未返回 usage 时计入 `unknownUsageCount`，不估算。计划和记录中预留 `budget` 字段（默认 `null` 表示不限），本批不实现拦截。

**R6 API。** `GET /api/automation/status`（全局暂停、调度器健康、单实例信息、下一次运行）、`GET /api/automation/schedules`、`PATCH /api/automation/schedules/:type`（启用、计划、catchUp，带 revision）、`POST /api/automation/pause`、`POST /api/automation/resume`、`POST /api/automation/tasks/:type/run`（手动立即运行）、`GET /api/automation/runs?type=&status=&limit=`、`GET /api/automation/runs/:id`、`POST /api/automation/runs/:id/cancel`。写操作走既有本机门禁。

**R7 UI。** 侧栏“自动化”页面：全局暂停开关（带确认）、任务列表（启用、计划、下次运行、最近结果）、编辑计划、立即运行、运行历史（筛选、详情含步骤/错误/用量/产物链接）、取消运行中任务。首页自动化状态卡。界面如实说明“仅在工作台进程运行时执行；关机期间错过的任务开机后最多补跑一次”。

**R8 内置任务 `system.selfcheck`。** 默认每 60 分钟：检查数据根可读写、单实例锁一致、`/api/recovery-issues` 数量、Provider 是否已配置（**不发起调用**）、磁盘剩余空间；只写运行记录。用于证明调度、补跑、暂停、记录与 UI 全链路，模型调用 0。

## 验收项

- **RUN01-01** 生产模式：`npm run build && npm run start`（TEMP 数据根、非用户端口）后 UI 与 API 同源可用；刷新深链接正常；`/api/*` 不被 SPA 回退吞掉；跨源/伪造 Host 写请求仍被拒绝。`npm run dev` 回归可用。
- **RUN01-02** 单实例：同数据根第二个进程（生产或开发）被拒并提示；杀掉进程后可接管；不同数据根可并存。
- **RUN01-03** 调度语义（fake 时钟单测）：daily/interval 下次时刻（含上海时区跨日）、不重叠、暂停→skipped、启动标记 interrupted 且不自动执行、错过计划补跑恰好一次、`catchUp:false` 不补、取消、revision 冲突、保留策略。
- **RUN01-04** 运行账本：原子写入、损坏记录不导致调度器崩溃（单条报错可见）、备份导出/恢复包含 automation 数据且校验通过。
- **RUN01-05** 用量计量：fake Provider 在自动化上下文中被调用 N 次时 usage 准确；无 usage 字段计入 unknown；普通用户请求不计入任何运行。自动化上下文调用正式 Wiki/Prompt 写入被拒绝。
- **RUN01-06** 真实常驻：验收者用参数化的测试任务名与 TEMP 数据根运行安装脚本，`schtasks /Run` 启动后健康检查通过、`system.selfcheck` 至少按计划自动运行 2 次（可把间隔设为 1–2 分钟）；手动结束进程后计划任务自动重启（或如实记录 Windows 行为）；卸载脚本后任务与进程均不存在。不得注册或修改用户正式任务名。
- **RUN01-07** UI：真实浏览器 1440/390 宽度完成暂停/恢复、编辑计划、立即运行、查看详情、取消、首页状态卡；控制台无错误；截图存证。
- **RUN01-08** `npm run check` 通过，CI 绿；产品运行不依赖 Codex/Agent CLI。
