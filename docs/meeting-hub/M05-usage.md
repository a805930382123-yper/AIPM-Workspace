# Meeting Hub 本机使用说明

Meeting Hub 通过左侧“会议档案”进入。本地服务只在 `127.0.0.1` 提供页面和 API；会议目录、会议元数据、策略、纪要版本和 Raw 收据保存在本地数据根目录。默认数据根为项目内 `workspace/`，也可在启动服务前通过 `FMCG_DATA_DIR` 指定。不要把真实客户资料用于未经授权的测试。

新建会议后，可填写类型、业务标签、客户/项目和飞书 HTTPS 来源。来源链接只在用户点击时打开新标签；页面不会自动抓取或预览飞书内容。会议元数据搜索不搜索纪要正文。

新建时可选择“保存并上传本地纪要”：先保存会议，再到该会议的本地纪要区选择文件并导入。若当前策略不允许导入，先在会议详情顶部的“安全策略”中设置本地归档；Internal 和 Sensitive 还需本地保存授权及单独确认。Public 在本地归档模式下可导入；Restricted 仅保存最少元数据，不能导入正文。上传失败后可在同一会议中重试。

本地纪要支持 DOCX、带文字层的 PDF、UTF-8 MD/TXT 文件或粘贴文本，上传文件最大 2 MiB；旧版 `.doc` 请先另存为 DOCX，扫描件 PDF 不做 OCR。上传后保存原文件和提取正文，原文件可下载；工作副本可单独编辑，再导入会追加新版本并保留历史。删除纪要和删除会议都需要明确确认。飞书上的文件不会随本机删除。

Raw 登记与纪要导入分开操作。仅 Public/Internal、使用本地归档并具备独立 Raw 登记授权的会议可以登记。用户必须选择一个纪要版本并明确确认；Raw 正文取选定版本的 `imported_minutes` 原件，不取编辑后的工作副本。登记成功后，Raw 列表和首页统计会从服务端更新；会议的“查看 Raw”可按 Raw ID 打开并定位阅读。若目标临时无法读取，页面会保留目标并提示不存在或已删除；点击“重新连接”会继续检查同一个 Raw。用户改选列表中的资料、通过普通导航打开 Raw 或完成删除后，页面按当前列表和正常默认规则选择。取消或在 Raw 写入前被拒绝不会创建 Raw。跨文件提交可能出现 Raw 已真实写入、会议关联收据暂时未完成的部分成功；此时 Raw 列表刷新后应按真实文件计入，会议记录保留 pending 状态。重新读取会议状态后，使用原来的请求执行恢复，不要新建请求重复登记。解除展示关联只改变会议页面关系，不删除 Raw；删除会议也会保留 Raw。删除 Raw 后，会议记录显示 Raw 已删除且不提供阅读入口。Raw 来源始终标为 `meeting_local_only`：禁止外部 AI、Wiki 沉淀与 Prompt 背景使用。解除关联、删除会议或修改普通字段都不会解除该限制。

常用本机路径如下：

- 会议目录：`meetings/catalog.json`
- 会议记录及本地纪要版本：`meetings/records/<meeting_id>.json`
- Meeting Raw：`knowledge/raw/meetings/<raw_id>.md`
- Raw、Wiki、Prompt 等既有资料仍沿用原目录和存储格式。

导出与恢复使用现有工作区备份 CLI。备份覆盖 `knowledge/`、`prompts/`、`drafts/`、`state/` 和 `meetings/`；导出前停止本地服务以避免并发写入。恢复目标必须是不存在或空的新目录，不能覆盖已有非空数据。恢复和校验细节见项目根目录 README 的“首页、教学数据与备份”章节。

会议页面不自动灌入演示资料。应用没有会议播放器、会议 AI 或云部署能力。修改会议来源只保存索引元数据，不会改变飞书权限；本地备份也不提供磁盘安全擦除或云端清除。
