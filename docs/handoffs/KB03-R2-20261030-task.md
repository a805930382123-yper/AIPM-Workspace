流水线冻结为：
1. 本地结构扫描：连续offset保存标题/段落/列表/表格行等线索，绑定Raw SHA，不将Markdown样式当事实；原文完整保留。

5. 确定性质量检查后执行一次模型辅助质量检查；得到只读质量报告，不自动修改正文。最后原子保存带structuredNote的新草稿及质量报告，全部页未选择、HUMAN未批准。任何未完成阶段不产生成功草稿。

## 校验与能力边界

深度schema严格未知字段、版本、ID/引用/数量/输出大小限制，沿用secret扫描和Provider错误脱敏。所有引文offset及Raw SHA仍核验。写作模型不得重定义事实目录。数值/日期/单位检查基于正文所属引用事实，保留原数值与单位/条件；至少阻断100家→120家、20%→30%及单位替换等固定反例。用已验证引用逐叶核对，不能仅在全篇找相同数字就通过。不能把纯schema、数字集合检查称为完整语义真实性证明；自然语言主体/条件重组仍需模型提示和后续人审，报告明确此局限。
补充内容遵守提案受限策略：不含具体公司数据、日期、数值、排名/预测；可机械检查部分必须阻断并测试。比例按“承载角色的叶项数”统一计，不超过20%；补充独立条目/段落，不能掺入source_facts。模型辅助输出严格结构（发现项severity/category/section或block位置/reason），分清通过/警告；它不能覆盖确定性失败，也不能成为自动正式写入授权。模型指出语义问题可保存质量警告草稿（本轮正式禁用），报告非“质量全过”；模型响应无效/请求失败则阶段失败，不伪造检查完成。
质量报告/覆盖/结构扫描保存在深度checkpoint，草稿带有必要只读版本化qualityReport/深度标识以供R3读取；新可选字段缺省不影响旧草稿，受candidateContent摘要绑定，HTTP patch不可伪造修改。R1公开创建/编辑新笔记拒绝门禁保持；仅内部流水线经验证的创建参数允许原子保存，不能把HTTP传入字段直接透传。

## 调用、恢复及并发

实际基础链revision13为N次chunk分类+1次知识页规划。本轮新增大纲1、写作1、模型质量1，所以无失败深度最少N+4次Provider请求，单块5次；结构扫描/确定性检查不调用。若原函数隐含额外调用，施工必须在自检揭示并报主线程，不能漏记。深度单job上限冻结为2*N+8（为显式恢复保留有界空间），standard原min(128,2*N+4)不变。此为本地每job工程限制，不是新增真实请求授权。预检预算须容纳全部剩余阶段；每次发送前持久化attempt累计，失败/非法响应也计数，不自动重试、不因继续或重启程序清零。
checkpoint pipelineVersion='kb03-1'；复用既有原子写/串行队列/任务状态/存储reconcile机制，不创建通用调度框架。严格绑定raw ID/SHA、mode、规则版本、Provider非敏感身份、chunk描述、已验证阶段产物及attempt；旧KB02记录仍按原分支校验。done需有真实草稿且新字段、任务ID、SHA、预算相符。缺失/损坏/身份变化停止并保留原件，不能自动以新账本重新发送。
用户再次显式发起同模式提取（restart=false）才恢复，复用完成阶段，失败阶段重试计新attempt；restart=true明确另起任务，保留旧账本。GET/重启初始化/reconcile-storage只恢复本地状态不外发。已完成阶段输出未落盘时不能保证网络exactly-once：发送前已记attempt，重启后视未完成，显式继续可能重复该次请求并新增计数，必须向任务错误/恢复提示如实说明。完成保存失败优先仅重试保存，不重调用模型。
双击同Raw同模式复用/拒绝已有运行任务，不产生第二套并发请求；跨模式也不能绕过同Raw占用。cancel期间Provider晚到响应不得产生有效草稿或覆盖新任务；进程重启不自动重发。保留容量限制和现有失败状态，不能把partial称completed。
所有带structuredNote的正式create/update/commit/recovery门禁保持拒绝；本轮不会把笔记写进Source正文。
