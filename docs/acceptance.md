## 1. 状态、边界与证据

每个 ID 单独记录 `DOC`（文档/静态检查）和 `RUN`（真实运行）两种结论。正式交付的“已完成”以 `RUN` 为准；纯文档交付项以 `DOC` 为准。

| 状态 | 定义 |
|---|---|
| PASS | 本次冻结版本满足该项，证据可复查。运行项必须实际执行对应操作并检查结果。 |
| FAIL | 本次冻结版本存在可复现的需求偏差；附触发步骤、预期、实际、证据和根因标识。 |
| BLOCKED | 已实现且尝试验证，但被缺凭证、网络、环境或需用户明确的需求阻断；记录阻断与解锁条件，不能算通过。 |
| NOT_RUN | 尚未实现、尚未轮到、未执行或证据不足。未来批次保持此状态，不能因未实现而提前判 FAIL。 |

`DOC=PASS` 只能说明设计、规则、代码或说明具备所述能力。测试替身、mock、离线固定响应可以证明 JSON 契约、错误处理和审核门禁；不能证明实际 Provider 调用、长文提取、内容质量或真实 AI 主线通过。浏览器按钮存在、API 返回 200、构建成功均不能单独证明闭环。真实运行包含实际启动的产品、浏览器操作、API/文件结果核对；文件解析必须使用实际对应格式文件。真实 LLM 成功路径需要真实 Provider 和有效凭证。

一份场景证据可支持多个 ID，但记录必须逐项判断。每个证据至少含：冻结 commit/版本及变更范围、时间、环境与启动命令、数据目录、fixture 名称、操作/命令、预期与实际、关键截图或日志/文件快照、对应 ID、结论。报告不展示 API Key、完整鉴权头或业务敏感资料。截图验证交互，持久化文件/数据库查询验证真实保存；重启使用同一数据目录。数据断言用 ID、计数和内容摘要，避免输出整篇长文。

最小记录格式：

```text
B04 / <版本> / E04-01
覆盖：A08–A13、R12–R14
DOC：PASS | RUN：PASS/FAIL/BLOCKED/NOT_RUN（逐项列出）
步骤：<可复现最短步骤>；预期：<需求行为>；实际：<观察结果>
证据：<截图/命令输出/持久化快照路径>；环境：<Provider/模型或 mock>
问题：<根因 ID>；修复：<变更版本>；复验：<次数与结果>
```
