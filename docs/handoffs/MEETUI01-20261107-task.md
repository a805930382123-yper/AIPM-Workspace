## 冻结最小方案

沿已读取 frontend-design 与 DESIGN.md 紫白主题。保存为紫色主操作；删除独立危险区域、保留原确认复选框。局部显式定义删除按钮正常、hover、disabled 的文字/背景/边框，禁用仍清楚可读，不依赖全局 danger-button 的底色或整体透明度。

在本地纪要内容区域最下方（原删除确认区之后）添加清楚的保存栏，按钮固定名“保存会议档案”，配“有未保存的纪要”/“纪要已保存”/“暂无待保存内容”等简短真实状态。现有“导入纪要/新增版本”和“保存工作副本”主按钮统一到此处，避免两个看似不同的保存阶段。选择文件、输入粘贴正文、编辑工作副本本身均不发送保存请求；底部保存按当前模式调用原 importMinutes POST/FormData 或 save PATCH，仍使用既有 requestId、baseRevision、锁和冲突处理。

编辑工作副本与准备新增版本采用互斥操作：进入编辑前如有未提交粘贴/文件，提示先保存或清空；工作副本编辑中禁用新增版本输入/切换，保留既有输入，不默默覆盖、不顺序拼成“全档案事务”。现有新增版本确认与 capability 门禁仍必需；编辑取消保留既有语义。保存请求中禁用相关输入和重复动作，保证用户后输内容不会被成功回调清空。成功后清掉已提交粘贴、文件 state 及原生 file input、dirty；更新状态并显示成功反馈。失败保留输入与现有冲突处理，不能显示已保存；无改动时按钮可见但禁用，不再次 POST/PATCH。再次选择同一个文件应能触发正常新输入。

会议信息编辑弹窗底部现有“保存”改为“保存会议档案”，复用原 submit；成功反馈明确指会议信息已保存。新建保存可统一同名，保留“保存并上传本地纪要”既有流程。安全策略/目录/Raw 登记各自原动作不合并，不改变其授权或说明。
