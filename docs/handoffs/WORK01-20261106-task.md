## 用户流程

- 主导航新增“工作事项”，列表显示客户问题的标题、当前状态和有值时的跟进日期。空列表可直接新建客户问题，只填标题和客户反馈即可保存，初始为“待整理”。保留已关闭事项，能从列表查看及重开。沿 `DESIGN.md` 已批准的紫白界面和现有响应式结构，首页原有四入口继续使用。
- 详情分为“当前情况”“处理记录”“资料与成果”。当前情况可保存状态、客户、项目、发生时间、等谁／等什么、下一步、跟进日期。客户、项目为可选手工文本，发生时间也是可选项，均可编辑、清空和回读。五个状态为待整理、处理中、等待处理、待复测、已关闭，可按现场情况人工切换。等待状态下显示设置跟进日期的提示，空日期、等待对象和下一步均可保存。关闭时显式填写原因，重开时明确操作，关闭与重开保留在同一事项的处理记录。
- 处理记录分别保存原客户反馈、补充反馈、复现、已发送技术反馈的正文与实际发送时间、技术回复、复测记录和关闭／重开。技术反馈正文由用户编辑和复制，只有单独选择“记录已发送”并确认正文与时间才形成发送记录。技术回复只留下回复内容，复测结果由用户独立记录，通过／未通过清楚可见。记录回复、复制正文、记复测和切换状态各自独立，允许还未收齐材料时推进或回到先前状态。
- 资料与成果可选关联已有 Raw，通过原页面按同一 Raw ID 打开原文，已有译稿的 Raw 也从原文打开。Raw 被删时明确显示来源不可用，不跳到其他 Raw。截图支持 PNG、JPEG，上传前可填写人工说明，保存后显示并可打开预览。图片不进入 Raw 导入、解析或索引。页面各项资料和记录来自实际输入与保存结果。
- 首页提供“到期跟进”，按上海自然日列出所有 `followUpOn <= 今天` 且未关闭的客户问题，显示日期并打开对应详情。没有日期、未来日期、已关闭事项不列入；延期、清空日期、关闭和重开均按保存后的记录重新计算。进入首页和手动刷新重新请求，保留原整理任务、草稿／稍后处理、工作流、Audit 及周期回顾的入口和语义。跟进来源读取失败时单独显示失败，原首页行动仍可使用。

## 数据和 API

- 单事项原子 JSON 记录 `work-items/<uuid>.json`。基本字段为 `id`、`revision`、`createdAt`、`updatedAt`、`title`、`feedback`、`status`、可选客户 `customer`、项目 `project`、发生时间 `occurredAt`、等待说明 `waitingFor`、`nextStep`、`followUpOn`、手动反馈正文 `reportDraft`、关联 `rawIds`，以及处理记录 `history` 和截图元数据 `screenshots`。客户和项目直接存文本，发生时间沿用发送时间的有效时间戳格式。状态值 `triage | in_progress | waiting | retest | closed`。处理记录最少保存种类、正文和时间，复测另有通过或未通过。首次反馈保存为 `feedback`；补充记录追加，关闭及重开记录由用户显式保存动作产生。清空跟进日期使用 `null` 或表单空值，存储为缺省；只接受有效的 `YYYY-MM-DD` 日期。关联写入验证 Raw ID，对合法关联去重，读取不改 Raw、RawState、Wiki 或其他工作数据。
- `GET /api/work-items` 返回 `{items}`，`GET /api/work-items?due=1` 返回到期记录摘要，供首页单独读取。`POST /api/work-items` 接受 `{title,feedback}`，返回新事项。`GET /api/work-items/:id` 返回详情。`PUT /api/work-items/:id` 带 `baseRevision` 更新当前情况／手工正文／Raw 关联，或追加一条类型化处理记录；关闭时包含 `closureReason`。复用现有 `SerialQueue`、`writeJsonAtomic` 和错误格式。并发更新必须检查 revision，过期返回 409；读取、校验、写入失败要给真实错误，页面保留待保存内容，成功后使用返回的新 revision。列表读取损坏记录须报错并保留原文件。现有工作区没有 `work-items/` 时直接读空列表。
- `POST /api/work-items/:id/screenshots` 用 `multipart/form-data` 单文件 `file`、`baseRevision` 和可选 `note`，返回更新后的事项。`GET /api/work-items/:id/screenshots/:screenshotId` 只返回已登记且归属该事项的图像，发送明确图像类型。服务端接收上限 5 MiB，按 PNG/JPEG 类型及文件签名拒绝其他格式、伪装类型、空文件，路径和扩展名由服务端生成。元数据保存图像 ID、图像类型、说明及上传时间，二进制放在 `work-items/screenshots/<workItemId>/<screenshotId>.(png|jpg)`。先完整保存图像再更新事项，在保存失败时避免提交指向缺失文件的记录，可撤销本次未登记图像。现有备份／恢复白名单加入 `work-items`，沿用 v1 归档及其既有安全与完整性校验。旧归档没有该目录时仍可恢复。

这批只交付手动客户问题及首页基础跟进。不接入 AI、OCR、自动发送、Wiki 沉淀、产品分析、后台推送、定时任务、通用任务引擎或新依赖。不接触正式 `workspace`、用户服务或真实模型和凭据。Stop That Shit 已在 `change` 模式，交付记录沿 Git 版本和精确差异，无额外 checksum 机制或文件哈希验证。

## 独立验收标准

| ID | 必须观察到的结果 |
|---|---|
| W01 | Chrome 从工作事项用标题＋客户反馈建立一条事项，初始待整理，刷新后正文和 ID 保留。编辑客户、项目和发生时间，保存重进后可回读，也可清空。可人工跨状态切换，等待时有日期提示，空日期也能保存，等谁／等什么和下一步分别回读。 |
| W02 | Chrome 保存反馈／复现，编辑和复制技术反馈；复制后没有发送历史。手工登记已发送正文与时间，补技术回复后没有复测通过记录。独立保存复测结果，关闭带原因后可找到历史，同一 ID 重开后仍保留全部记录。 |
| W03 | Chrome 上传合成截图，看到人工说明和预览，重进详情可再次查看；通过关联按指定 Raw ID 打开原文，包含已有译稿的 Raw。隔离 HTTP 检查 PNG/JPEG、拒绝伪装／超限／不归属图片，Raw 原文及处理状态前后相同，坏来源得到明确提示。 |
| W04 | Chrome 与隔离 HTTP 检查今天和逾期项出现，未来／空日期／已关闭项排除，首页项打开同一 ID。延期、关闭、重开后进入首页或手动刷新读到当前结果；固定时刻用例覆盖上海午夜两侧。旧首页 Raw 整理或草稿／暂缓回路实际可用，现有工作流、Audit、周期回顾定向回归通过。 |
| W05 | 隔离 HTTP 核实非法日期、缺标题／反馈、过期 revision 与保存失败均不会制造成功状态或覆盖较新数据。用实际 `scripts/backup_workspace.ts` 导出并恢复到独立新根，重启服务后经 HTTP 回读同一事项、处理历史和图像原字节，并能打开备份中的关联 Raw；旧备份无工作事项目录可恢复。 |

施工自查及独验用真实 `server/index.ts`、空 envDir 构建、隔离数据和 Chrome，宽窄视口至少各检查一次受影响页面。独验运行完整 TypeScript 检查、受影响的 `auto02-actions`、`lifeos-l3-*`、`lifeos-l6-review*`、`app-navigation` 和备份定向回归，可复用同一交付差异上的重复低风险检查并注明出处。若旧首页回路需要生成，使用隔离配置与本地 fake HTTP。证据记录实际命令、操作、结果、Git 基线和受验的精确文件差异。全仓测试矩阵不重跑。
