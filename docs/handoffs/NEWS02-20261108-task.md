## 最小筛选规则

不引模型分类器、评分框架或模糊聚类。确定性规则覆盖下列固定正反例并用少量可读规则实现，优先扩展现有函数。

- 快消：食品饮料、日化等明确消费品品牌/产品，商超便利店/零售渠道经营、供应链及消费品经营数据。仅有“品牌/新品”但对象为汽车、地产、手机等非快消不入选；农业收储、宏观口号、一般公司财报不为凑数入选。既有可口可乐战略、咖啡市场、批零发展、连锁便利店新品保持可选。
- AI：模型/智能体/工具的实际发布、功能更新、可核验评测及可用工作流变化优先；保留已有GPT Image评测、Cursor语音智能体、ChatGPT表格分析。仅融资/估值/芯片贸易、明星公司名或普通业务API不入选；真正同时含可用产品变化的新闻不能因融资词一律删去。
- 日期窗口及未来/未知日期排除保持；日期只有年月日时按上海零点解释，同一时间解析结果同时用于窗口与排序，不能排序时回退默认UTC。排序先24h内（快消），再明确经营/产品变化或评测优先级，再真实发布时间降序，最后规范URL作稳定平局键；规范URL等键仍相同时继续按sourceId、itemId、原URL、完整标题、excerpt的固定文本顺序破同分，完全相同记录等价，保证来源并发返回顺序不影响保留结果；AI全部24h内，采用同一实用性/日期/URL顺序。只在材料明确具备信号时加优先级，不生成业务影响结论。不强行来源配额，不补齐不足条数。
- URL去重统一去hash、去明确跟踪参数 `utm_* / fbclid / gclid`、排序其它query；保留身份参数和协议，不把任意query都删掉。规范化函数可复用，因为选条和保存身份都使用它。先排序后去重，再限额（快消最多5，AI最多3）。同栏同次及过去7个上海日期已展示记录再按“规范化后完整标题”去重（空白/标点/大小写归一，保留数字/版本号）；不做相似度、子串或主题级去重，GPT版本不同仍保留。旧期记录只用于读取比较，不重排改写历史。

## 主动保存契约

每条资讯按钮“保存来源摘录到 Raw”。旁边明确：仅保存已取得的摘录/来源摘要，后续AI整理需在Raw中另行操作；不称为全文。点击保存本身无网络抓取、无Provider、无提取任务、无草稿、无Wiki写入。分析仍留在原期刊 `analysis`，不混入Raw正文。历史及失败回退条目也可主动保存，使用实际所属期刊日期。

Raw `body` **严格等于服务器已保存条目的 excerpt**，不加AI fact/why/impact，不改写和拼接解释。保留原 title、sourceName、url、publishedAt（null时省略，绝不代入期刊日期）；sourceType=article、tags含每日资讯/栏目及材料等级。材料等级优先用现有 extractionNote 与可见标签表达，sourceName保留真实来源名并明确摘要等级以沿旧审核展示传播；不使用受会议策略约束的 origin，AIHOT须明确“来源摘要，未核验原文”，不是已抓取原文。期刊日期、fetchedAt、evidenceKind、sourceId和itemId在保存收据保留。正文SHA可与excerpt核对。Raw初始unprocessed，沿已有列表和详情读取。

服务端从已存期刊date/section/itemId取条目，客户端不传正文、来源元数据或Raw ID。只接受ready/source_only的实存条目；不存在404，非可保存状态409，损坏原件明确错误不覆盖。

幂等按规范URL（跨栏目/跨期相同链接同一条保存身份），不是客户端随机requestId。第一次成功的来源快照保持；后续同URL内容变化不覆盖已存Raw。用现有 `SerialQueue`/`writeJsonAtomic` 实现小型专用收据：`state/news-saves/<sha256(normalizedUrl)>.json`，schemaVersion1、原始期刊定位、固定rawId、保存输入快照/摘要、状态pending/linked、时间。首次先原子写pending，再创建固定ID Raw，再写linked。采用RawStore的服务端窄登记方法复用既有序列化/完整性校验；不得开放普通Raw接口传固定ID，不借用createDemo或会议origin。无需通用事务框架。收据中输入限于已有有界excerpt，不存AI分析。

重复/并发点击和丢响应后重试都返回同一实际Raw；重启后pending只在用户再次点击保存时恢复，复核已有Raw和冻结输入一致后补linked，不自动外发或覆盖Raw。重试/重启遇pending但Raw缺失时不能区分未写入与写后被用户删除，返回409明确“保存未完成且未找到Raw”，本批不自动补建；保留收据供核对，不新增删除门禁。linked对应Raw被用户删除时返回明确 `missing`/409，UI提示“原Raw已删除”，不自动重建，不跳到其他Raw；本批不加重新创建功能。收据损坏/Raw内容不匹配明确失败并保留文件。写pending失败零Raw；Raw已写但linked失败须说明“保存状态待核对，请重试”，不能报纯失败引导重新创建。正常已有linked读回核对Raw存在。服务仅单本机进程，与现有运行约定一致，不加多进程锁框架。

保留旧edition schemaVersion1，无保存字段也可读，保存收据独立不修改期刊正文及分析。备份既有state根自然覆盖收据，做真实往返验证。旧无news-saves备份兼容。

## HTTP / UI与所有权

现有NEWS读接口保持；可附加仅用于显示的保存投影，不回写旧期刊。建议接口冻结为：

| 方法 | 路径 | 输入/返回 |
|---|---|---|
| POST | `/api/news/editions/:date/items/save-raw` | JSON `{section,itemId}`；200 `{rawId,status:'saved',created:boolean}`；复用原NEWS本机/Origin/JSON guard；错误区分missing/conflict/pending，不暴露正文 |
| GET | `/api/news/editions/:date/saved-raws` | 只读当前期刊条目的 `{section,itemId,rawId,status:'saved'|'missing'|'pending'}` 投影；无收据不列；损坏明确错误；无写盘/模型 |

RawStore新增窄server-only方法的命名可由施工确定，语义是固定ID创建或核对完全相同记录；不得由客户端调控。NewsService通过明确依赖注入RawStore/窄桥，不把业务写入路由散落在UI；不修改LLM装配行为。

NewsPage接收 `onRawChanged`（沿App refresh）与 `onOpenRaw(id)`（沿真实nav，原文模式）。保存成功及时刷新列表/统计；显示“已保存 · 查看Raw”，由用户点击查看，保存结束不抢导航。刷新后、历史、回退均恢复正确状态。保存期间只禁用对应按钮，失败可读且可重试；切期/离页迟到响应不覆盖新期状态、不主动跳页。若保存成功但列表刷新失败，保留真实成功及rawId，不改成未保存。来源外链和文字安全渲染沿旧实现。1440/390可读，沿DESIGN.md。主Agent已运行impeccable context（SCOPED_EXISTING_ALLOWED）；施工UI前读craft-floor，结束detect一次。
