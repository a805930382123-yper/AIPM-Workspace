# AUTO02 第二阶段：从首页继续原整理任务

用户授权交付首页一任务一卡、整个任务的“稍后处理”和跨页面继续原草稿。基线为 main `4a92d63abfc2a4c263f2b2e89ea259203606c09a`。AUTO01 已通过工程验收，本批沿用既有整理、审核和提交事务。AGENTS、产品说明、两份历史 JSON 及未跟踪历史证据有既存本地改动，保留并排除在本批提交外。

评分 1/2/2/0＝5，B 模式。阶段二目标清楚，暂缓作用范围与入口是局部交互取舍；跨首页、整理状态、草稿和提交恢复；错误路由或并发状态变化会影响已冻结提交及历史草稿；阶段二无既有实测失败。Astra 启动停在 pending_init 后，用户批准 GPT-6.1 Sol High 替代本批规划和独立验收。实际规划/独验为 `/root/auto02_review`，施工为独立实例 `/root/auto02_builder`。主线程调度、管理状态和提交。

## 范围与接口

1. **同一整理任务一张首页事项卡。** 扩展 `GET /api/home/actions` 和现有详情校验，保留 `kind`、`id`、`target`、`versionToken` 及来源错误隔离。按当前 Raw 状态、同 Raw 的 job 及其实际绑定 draft 关联，校验正反向可用标识；禁止仅按 Raw ID 或标题合并。显示整理中、失败/状态待恢复、待审、已有成果入库且仍有剩余、提交待恢复、稍后处理。待保存恢复优先于同任务的草稿卡。未完成的提交从原草稿继续。旧草稿缺可验证绑定时保留现独立入口；不同 job 的历史待审草稿不吞并。已确认、无需变更、结束、全部不采纳保留 Raw 历史出口并退出待办。工作流、Audit 和周期回顾保持可用。缺损关联明确报错，不能打开另一条 Raw、另一份草稿或误报为空；继续沿当前 409 版本变化、410 目标失效、503 来源错误语义。首页复入、整理结算或手动刷新能读到最新状态，复用已有刷新，不新建通用任务轮询。
2. **暂缓是显式的草稿级状态。** Raw 整理的 maintenance Draft 新增可选 `deferredAt`，旧记录缺省未暂缓。通过 `POST /api/drafts/:draftId/defer`，请求 `{baseRevision:number,deferred:boolean}`，返回现有 DraftView。只接收仍待审、仍有剩余成果并正确关联 Raw 的草稿；复用现 Wiki 锁和 DraftStore 队列，检查 revision。无状态变化的同版本请求不制造新修订。变更只更新标记、revision 与更新时间；不改候选、主题证据、已提交 changeId/operationId 或正式记录。提交尚未完成时拒绝暂缓，包括已冻结但尚未完成的原事务；不能仅凭有无 operationId 拒绝已完成部分提交。暂缓期间明确恢复后才能发起新的正式确认。已有合法事务的重试语义沿原服务。范围内只需窄接线，保留真实权限及提交门禁。
3. **原页审核，跨页继续。** 在现 Raw 成果审核页提供“稍后处理”，仅在可审核且没有未保存编辑或进行中操作时可用，说明将保留已保存成果、稍后仍需确认。未选成果不自动暂缓，也不承诺跨页保存临时勾选。操作后从首页行动区的“稍后处理”区或 Raw 状态重新打开同一 draftId，再明确“继续处理”解除暂缓；打开本身不清标记、不发模型请求。未暂缓待审任务按原入口继续。保存失败显示原状态并可重试。部分提交后原已入库成果只读；其余成果可重新选择，最终仍由人工明确确认。保留“结束选择/全部不采纳”现有历史语义。保留 DESIGN.md 已批准首页和审核页布局，使用现有样式和响应式结构，不增加顶级导航。

批次限于现有工作台的任务呈现、暂缓和继续。继续复用原 job/checkpoint、Draft、WikiCommitService、Raw 及权限判定。真实模型调用为零，沿用历史账本；真实目标重准备、deep/长文生成质量属于既有待验证范围。

## 独立验收标准

| ID | 验收 |
|---|---|
| T01 | 实际 API 和 Chrome 从 Raw 开始整理，离开后首页仅一张同任务卡，读得到运行和结算后的原草稿。故意制造恢复状态，原任务只显示优先恢复入口。另一个合法旧草稿和 Workflow/Audit 保留。 |
| T02 | 实际 Chrome 从原审核页显式暂缓，服务端草稿读盘出现标记。返回首页进入“稍后处理”，刷新后仍在，打开同 draftId 时标记仍在；显式继续后移回待处理。Raw 原页也能找回同草稿。暂缓、刷新、打开、继续均不生成新 job、模型调用或正式写入。 |
| T03 | 先确认一个成果再暂缓和继续，已写成果的文件版本、operationId、来源及已存编辑保持，确认剩余项后首页移除且真实 Wiki 可回读。未选/结束/全部不采纳不产生暂缓项。提交待恢复可进入原事务，暂缓和陈旧请求被拒，重复确认不重写。 |
| T04 | 隔离 HTTP 与文件证据核旧记录读取、缺失/错配引用、扫描单来源失败、失效事项版本和 revision 冲突。核对 Raw 内容指纹、草稿/事务/正式文件前后状态。实际浏览器检查首页、审核、Raw 的状态文案和回路，桌面和窄视口各检查受影响区域。 |

施工自查和独验使用 TEMP 合成数据、真实 server/index + 空 envDir Vite 构建及本地 fake HTTP，Chrome 以本机实际可执行文件启动，保留操作证据、命令、结果及 SHA。回归至少覆盖 `lifeos-l3-actions`、`lifeos-l3-navigation`、`lifeos-l6-review`、`app-navigation`、`lw01-raw-ui`、`lw01-actions`、`lw01-recovery`、`rawux01-http` 及改动直接触及的测试，运行完整 TypeScript 检查。独验复用旧不变模块证据时列明 SHA 与覆盖边界。正式 workspace、用户运行服务及真实凭据保持隔离。
