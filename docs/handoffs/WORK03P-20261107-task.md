## 实物依据与最小实现

`app/pages/WorkAnalysisPanel.tsx` 的 `stageDraft` 当前将 roundSummary、所有主题、所有观察及原文、全局建议和问题完整拼接。原模拟第二轮带入曾达 3670 字，已由人工另存摘要。`AnalysisThemes` 当前将模型的 `evidence_supported` 直接显示为“有证据支持”；实际第二轮同一主题包含 Q07/Q14 异常表现与仍缺证据的 Q18，不能让主题标签代表全部案例。

1. **v2 默认带入简短草稿。** 以完整既有 `roundSummary` 为主体，保留“AI 草稿／待确认”说明；不再自动拼接主题全文、观察和引文、全部建议。追加简短待核段：将主题及全局 openQuestions 按原顺序合并去重，仅带入前 2 条，每条最多 120 字；如截短加省略号，超出条数明确提示其余待核问题见原分析。如有 `confirmedConflict`，明确写出冲突总数与首条 suggestedRevision（最多 160 字，截短显式省略），提示在原分析逐项核对，不改变已确认结论。正文提示“完整证据、反例与其他建议见原分析”；沿用 `analysisRunId` 及原轮次入口，不另外复制原文。不按 Q18 等特定样例硬编码。正常本轮样例带入不超过 1200 字；用户仍可自由编辑。
2. **保留已有阅读、编辑和保存。** 完整主题、观察与原文在原分析可读可定位。沿用非空编辑阻止覆盖、手动保存及来源追溯；不自动落盘。不改 v1 的旧带入规则，不改已保存历史、既有运行记录或 request/output schema，不增加“简版/详版”设置或额外模型调用。
3. **标签准确表达来源和范围。** evidence_supported 显示为“AI 标注：有支持材料（待核对）”，hypothesis 与 null 保留明确待验证语义；在每个支持主题邻近显示“支持材料不代表同主题每个案例均已证实；证据不足的判断仍待核实。”保留正文中 Q18 等明确限制及待核问题。不得称系统已验证语义支持，不通过关键词猜测重写历史结论。v2 带入不再复制旧的“有证据支持”标签。
4. **小幅修订现有 systemV2。** 明确 `evidence_supported` 只描述其实际有支持的具体判断，不能由“至少一个支持观察”推成主题下所有案例有证据；不同证据状态优先拆主题，若同主题比较则在 conclusion 与 openQuestions 逐项点明已支持/待验证范围，不能把记录了反馈当作已证实异常。roundSummary 保留关键不确定性、反例限制与确认结论冲突，不为简短省掉这些限制。只修改现有提示，不改结构校验或新增语义判定。静态提示检查与 fake 验证不等于真实模型遵从性验证。
