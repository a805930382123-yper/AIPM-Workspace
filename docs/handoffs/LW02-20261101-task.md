## 冻结语义接口

具体TS字段/路由名由施工者定并交接列出；以下语义不可省略。

### 1. 单问题结果与引用

问答记录具有真实resultId/revision、原问题、状态、分段答案、实际读取的Wiki快照（id/revision/body/sources）、必要Raw片段（rawId/bodySha256/start/end/quote）、引用目录、去重底源集合、Provider尝试/错误、可选已生成draftId。检索候选、实际已读页、答案实际引用集合分别记录，不能混为使用过的证据。只保存当前问题及必要回存状态，不开发聊天会话列表。可置于`state/knowledge-answers/`等既有state子目录，以便刷新/失败恢复；不得进正式knowledge或伪造原始资料。

答案先直接回答，再按必要程度列依据；结构明确标识来源事实、跨源综合/推断、建议、信息不足/分歧。年份、主体、统计口径不混同；缺乏证据时直说无或部分依据，不补模型常识为已确认事实。推断与建议不能由保存动作升级为来源事实/已核实。没有依据的回答可以显示，但没有可沉淀事实时不得强制造草稿。

关键事实及综合依据必须引用本次实际读取且允许的页面/Raw；服务端对模型返回引用ID做目录白名单与真实ID/版本/Raw定位核验，未知/未读/越权/不匹配引用拒绝，不能静默生成漂亮假链接。事实段至少有真实依据；推断段清楚标记并列出其依据或不足。引用展示页名及版本、必要原文位置，点击打开正确既有页/Raw位置。Raw引用精确片段；Wiki引用关联其底源，不能把同一Raw的多个页面称多份独立来源。复用已有offset/导航与quote匹配，不新建字符标注平台。引用存在/版本/权限/本次实读校验不等于语义支撑已验证，UI不得据此宣称“回答事实已核实”。

### 2. 检索、必要原文与权限

首次检索实际读取选中Wiki正文及来源/版本；仅命中标题列表不算实现。沿用8页/48k上限和确定性排序，可从问句提取检索词但不加向量库/全库正文外发。无命中可直接返回无依据，或有界生成不足说明。

只有当前问题需要细节或冲突核对时，沿已读Wiki的来源补读Raw；实际补读必须可记录必要性和范围，不预先全读/全发底库。固定本批补读上限为3份Raw、累计24,000字符片段；片段保留真实UTF-16位置及哈希，不截断后伪装完整原文。选Raw的模型提议也必须被服务端限制为本次已读Wiki底源。可采用一次先读Wiki的结构化答复/补读请求，再一次有片段的回答；单次提问最多2次Provider调用，无隐式无限循环/重试。保留已用次数，失败重试需显式操作并披露状态。

上述“单次提问最多2次”指一次用户明确生成或重试执行内最多2次Provider调用；跨执行累计attempts不清零，首次两次失败不永久禁止显式重试，仍禁止自动重试及无界循环。

所有发给模型的检索正文、Raw片段、引用目录、引用查看和回存均沿底层Raw检查来源限制。meeting_local_only及缺失/损坏来源不得外发；衍生Wiki同样限制，不因人工改标题或经回答回存而解除。恢复/重新打开引用/保存前再次检查，不能缓存绕限。普通原始资料的本地阅读权限不被本批全局改变；本批问答引用接口/跳转在转交现阅读器前验证来源，受限后显示不可访问而不是继续显示缓存正文。文档内容是数据，提示词明确与系统规则隔离，不执行其中“忽略指令/泄露其他资料”等内容。

### 3. 保存预览与维护草稿

回答完成后提供保存全部或简单选段，用户可编辑预览；展示准备沉淀的结论、底源、事实/推断标记和建议新主题/已有目标。保存预览/取消都不创建正式Wiki/Source/index/log/反链，不创建Raw。用户明确“生成草稿”后才创建或返回维护Draft；不是点击查看答案即回存。

保存时重新检索并读当前相关Wiki，包括拟更新目标的正文/版本/来源。已有容纳主题优先更新同真实ID；确实新专题才create；已有覆盖/无实质新增返回清楚的no_change状态，不强造新主题或无意义空版本。沿LW01生成完整候选正文，保留旧有效/人工内容和底源，年份/冲突并列。允许每次显式保存最多一次有界维护提议调用；计入尝试记录，无自动重复外发。

问答Draft增加可选`question_answer`输入快照：回答ID/版本/已选段与人工编辑、真实依据Wiki版本快照、去重多Raw身份/哈希/真实引用、事实/推断类别。旧字段/旧草稿可读。实现可选择兼容可选字段或窄类型联合，但QA分支不占用旧rawId/rawSha必填位，不用虚构或空伪Raw、不把答案作为原文。允许无Raw底源的人工Wiki作为本地知识页依据，绑定真实Wiki ID/revision/正文，显示“人工知识页依据”，其Raw集合可为空，不能伪造来源数或原文位置。所有验证/来源/审批/恢复遍历全部真实依据，不能只检查一个主Raw。UI应显示问答成果和全部真实依据，不把答案标题显示为原始Source。

Draft的事实目录和humanReview应来自原始证据及明确标识的模型综合提议，回答文字不能冒充原文引文；Wiki人工补充可作为“知识页内容”证据，必须保留这种身份，不能伪造Raw位置。问答没有原始证据的推断/问题只能按该类别保留，不能自动已核实。正式页sources仍为底层Raw去重集合；可追加来源Wiki/答复ID作为审计元数据或明确派生标记，但回答ID不作为独立证据。后续再次引用该页能追到原底源及派生属性，不能回答→页→回答循环增加独立证据数/可信等级。

问答Draft提交不生成问答Source、不修改Raw正文、也不假装把某个既有Raw重新处理完成；只更新真实选中的知识页、索引/日志及问答回存状态。继续复用LW01的逐项接受/编辑失效/重审/暂缓、依赖、完整归属、版本/标题冲突、前快照、同key同payload幂等与恢复门禁，不绕开旧规则。

### 4. 版本、幂等与失败

提问、回答、预览、生成Draft、正式知识已更新状态必须区分；同时区分无依据/部分依据/失败。失败保留问题和已有成功答案，错误可读，明确重试，不伪装已完成或吞掉结果。

同结果的重复“生成草稿”返回同一个已创建Draft；双击、请求响应丢失、重启恢复不能产生多草稿。保存键绑定result/revision、选段与编辑摘要；同key异内容拒绝。若已有Draft后又编辑结果，允许明确更新仍待审Draft并失效全部受影响批准，或提示打开现有草稿处理；不得悄悄另建重复Draft。已正式提交的同结果重复保存返回既有结果或no_change。

回答后任一实用依据Wiki版本/底源发生变化，保存前提示过期并要求重新核验/生成回答，不能仅换成新revision而复用旧断言。重新验证实际读取和判断内容，保留旧答案供对照；未经用户确认的新结果不覆盖既有批准。Draft生成后的目标/依据版本变化仍于审核/正式提交和恢复拒绝，不能静默覆盖。权限收紧立即阻断，不因已有answer/Draft获得豁免。失败恢复沿现manifest冻结选集/输入摘要/目标版本与底源，不重复创建/增长版本/日志。
