# B01：本地骨架与可靠 Raw 文本导入

状态：2026-10-03 已完成并通过独立验收，8/8场景 PASS，报告见 `docs/reports/B01-acceptance.md`。目标：用户能够启动本地工作台，导入真实文本，刷新和重启后阅读相同正文；首页数量来自已落盘数据。

## 必做

1. React/TypeScript/Vite UI + Node/TypeScript 本地 HTTP；`npm run dev` 单命令启动，提供可构建/可测试脚本及 Windows 说明。
2. 五项导航，首页和 Raw 真正可用；其他三个入口清楚标记后续批次，不能放可点击的假功能。设计安静、桌面优先、中文界面。
3. Raw 文本表单：标题、来源类型、来源名称、作者（可选）、原发布日期（可选）、链接（可选）、标签、正文；八类来源对应原 PRD。空标题/空正文、错误类型、非法 URL、超长请求有明确错误。正文原样保留，不能 trim 原文。
4. Raw 列表/详情/导入；保存后显示全部字段、ID、导入时间与“未处理”。标题不可成为路径。数据保存在 `workspace/` 或 FMCG_DATA_DIR 指定位置。
5. Raw 为含 YAML 元信息的 Markdown，前后空白、中文、换行、`---` 等正文内容读回一致；正文 SHA256 可验证。先临时文件再 rename，失败不显示成功。不存在 AI 写入路径。
6. 首页显示 Raw、Wiki、本周新增、待确认、Open Audit、Prompt 六项实际统计；尚无对象为零。本周按 Asia/Shanghai 周一 00:00 口径，本批“新增”定义为 Raw+Wiki 新建数并在 UI 解释。Raw 导入即时刷新统计；首页导入快捷入口可用。

## 接口

`GET /api/health`，`GET /api/stats`，`GET /api/raw`，`GET /api/raw/:id`，`POST /api/raw`。

Raw POST 使用 `title/sourceType/sourceName/author/publishedAt/url/tags/body`。类型为 `wechat/article/report/company/customer/meeting/note/other`，映射 articles/reports/company/customer/meetings/notes/other 目录。输入验证在服务端完成。响应错误结构 `{ error: { code, message } }`。至少支持 100,000 字符长文，超过上限清晰报错；实际限制写入 README。

默认仅监听 localhost。不添加密钥，不请求产品 LLM。本批不实现删除/文件上传/手动 Wiki/Prompt CRUD/搜索/AI/导出/演示数据；不声称完整 MVP。

## 本批门槛

- 可在本机安装/启动/构建；空数据根目录初始化，持久化不依赖浏览器 localStorage。
- 通过浏览器导入中文长文并阅读；刷新后仍存在；重启服务仍相同。
- API 读回正文逐字符一致；原始文件 hash 在读取、刷新、重启后不变。
- 错误请求不增数据；UUID 与路径隔离；客户端请求无法指定任意写路径。
- 六项首页统计真实、导入后更新；未实施入口有明确说明。
- 无 LLM 配置时手动链路完整可用；测试使用隔离临时数据目录，演示/验收资料标识。
