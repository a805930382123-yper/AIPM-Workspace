# EVAL01 AI 质量评估基线 任务卡

属于 [AI 自动化路线图](../batches/AUTO-ROADMAP-20261114.md) 阶段 0，开发侧工具，**不进入产品运行时**。目标：把过去靠人工 gold 打分的质量判断，变成可重复运行的评估集与评分器——默认离线回放（零费用、可进 CI），需要时显式切换真实 Provider 跑一次并记账。之后改提示词、换模型或调整自动化，都能先看评估结果再决定。

## 评分与模式

需求明确度 1（评分维度需规划者细化）/ 模块耦合 1（只读调用既有 LLM 服务链与校验器）/ 变更风险 0（不改产品、不写正式数据）/ 历史失败 1（知识整理真实质量多次未过，评估口径曾有争议）= **3，A 标准**：Astra 规划，Sol High 先审计划，Terra High 施工，不同实例 Sol High 独立验收。

依赖 ENG01 PASS。可与 RUN01 并行（文件所有权不重叠）；不阻塞 PIPE01。

## 必做

**V1 用例格式。** `evals/cases/<chain>/<caseId>/`：
- `case.json`：链路名、输入（Raw 正文文件引用、模式 standard/deep、附加参数）、`license`（`synthetic` / `own` / `public-excerpt` / `copyright-local`）、来源说明、创建日期。
- `gold.json`：确定性检查——必须出现的事实（含可接受同义表达或关键数值/单位）、禁止出现的断言（编造数字、把预测写成事实、把推断写成原文事实）、必须保留的待确认点、字段完整性要求。
- `recordings/<recordingId>.json`：录制的 Provider 请求摘要（不含密钥）与原始响应，用于回放。
- **仓库是公开仓库**：`copyright-local` 用例（基于真实研报/付费内容）只放 `evals/local/`（加入 `.gitignore`），提交的用例只能是 `synthetic`/`own`，或经确认可公开的短摘录。

**V2 运行器。** `npm run eval -- --chain <name> [--case <id>] [--mode replay|live] [--recording <id>]`：
- `replay`（默认）：用录制响应替代 Provider，经过**与产品完全相同**的解析、结构校验、证据映射与组装代码，零网络。
- `live`：必须显式 `--mode live`；使用当前产品配置的 Provider；开始前打印将发送的用例数与预计请求数；逐次记录请求数/token/未知用量；可用 `--record` 把响应保存为新录制。失败不自动重试。
- 输出 `evals/results/<时间戳>-<chain>.json`（gitignored）与终端/Markdown 摘要；支持 `--baseline <结果文件>` 对比，显示各指标升降。

**V3 确定性评分器。** 至少包括：结构/校验通过率；证据保真（引文在 Raw 原文中逐字存在、位置正确）；必含事实召回率；禁止断言命中数；事实/整理/推断/待确认分区是否混用；重复率（同一事实重复陈述）；空主题/仅标题主题数。每项给出用例级明细，便于定位。LLM 评审（judge）不做或默认关闭。

**V4 种子评估集。**
- `standard-extract`（Raw 标准整理）：≥6 个用例，取自既有**合成**材料（`docs/reports/WORK05-SIM-20261108/`、`docs/reports/WORK-CLOSED-20261109/`、AUTO-REAL 合成样例等），并补充 ≥2 个专门构造的陷阱用例（预测 vs 已发生、口径/样本条件、数字单位）。
- 若规划者判断可行，`deep-extract` 或 `news-relevance` 可先只建格式与 1–2 个示例；`news-relevance` 的完整用例由 PIPE01 补充。
- 历史真实 gold（如 PDF01 六页 gold、KB/LW 样例）若在本机存在，可整理为 `copyright-local` 用例放 `evals/local/`，不提交；本机缺失则如实记录，不补造。

**V5 基线与 CI。** 对种子集录制一次真实响应（live，记账，无上限但失败即停），生成首份基线报告 `docs/reports/EVAL01-20261114-baseline.md`（只含指标与用例级结论，不含受版权正文）。CI 增加 replay 模式评估步骤（仅已提交用例），指标低于基线阈值时失败；阈值由规划者冻结并写入 `evals/thresholds.json`。

## 排除

- 不改产品提示词、规则或模型配置（发现质量问题只记录，作为后续批次输入）。
- 不做评估 UI；不进入产品运行时；不读写正式 `workspace/`。
- 不重算或改写历史真实验收结论。

## 文件所有权

施工：`evals/**`、`scripts/eval/**`、`package.json` 的 `eval` script、`.gitignore` 增加 `evals/local/` 与 `evals/results/`、`.github/workflows/ci.yml` 增加 replay 步骤（若 ENG01 已交付该文件）、`tests/eval01*`、`docs/testing.md` 评估小节、EVAL01 施工报告与基线报告。只读引用 `services/llm/**`、`services/wiki/**`；如需为可测试性导出内部函数，改动须最小且无行为变化，并在报告列出。
验收：只写验收报告与验收脚本。主线程：status、提交推送。

## 验收项

- **EVAL01-01** replay 模式经过与产品同一套解析/校验/组装代码（验收者通过注入一个故意不合规的录制响应，确认评估报告给出与产品相同的拒绝原因）；零网络（断网或拦截下运行通过）。
- **EVAL01-02** 评分器正确性：每个评分器有正反例单测；人为修改录制响应（删掉一个必含事实、加入一个编造数字、引文改一个字）时对应指标准确变化。
- **EVAL01-03** 种子集满足 V4 数量与 license 要求；提交内容无 `copyright-local` 材料、无密钥（扫描通过）。
- **EVAL01-04** live 模式：必须显式开启；实际真实运行一次，报告请求数/token/未知用量；失败不重试；录制可被 replay 复现同一评分。
- **EVAL01-05** 基线报告存在且与 `evals/results` 实际结果一致；`--baseline` 对比可用；CI replay 步骤在远端实际运行通过。
- **EVAL01-06** `npm run check` 通过；产品行为无变化（若导出内部函数，相关产品测试通过）。
