# 项目 Agent Router

本 Skill 是既有协作流程的入口，按引用加载原规则，除下方用户指定的 A 模式施工配置外，不另定义评分、角色、模型、推理强度或升级条件。以下链接从本文件解析；执行命令前定位包含这些文件的项目根，不依赖设备绝对路径。

## A 模式施工配置（2026-10-27 更新）

A 模式由 **GPT-6.1 Terra / High** 施工，实际创建参数为 `model="gpt-6.1-terra"`、`reasoning_effort="high"`；GPT-6.1 Sol 继续负责独立审查验收。此配置替代旧 A 模式的 Luna 施工安排，适用于后续 A 模式调度；历史记录中的实际模型身份保留。项目 coordination.md 的现行 A 模式规则须同步此配置，评分阈值、Sol 先审计划的条件、B 模式及升级门禁沿用原规则。

## 入口选择

- “检查项目状态”“切换电脑后恢复进度”、仅需协作建议：进入只读预检。
- “执行已批准批次”：只有用户明确批准目标及范围，且能与当前任务卡对应时才进入执行。结合本轮指令及既有授权判断，不重复索取已明确的授权；最新只读、停止或禁止同步要求必须遵守。
- 目标或授权范围不明确：停留在预检和建议，说明待确认事项。模式建议、历史授权记录、剩余额度和调用 Skill 本身均不扩大本轮授权。

## 项目状态预检

完整执行 [项目状态预检](../../../docs/coordination.md#项目状态预检) 中的检查顺序、证据要求和六项汇报。只检查和建议；不派发施工、不修改状态、不自动同步，不以探测配置为由调用子 Agent。报告区分本次实查、历史报告和未验证项，汇报后停止。

## 执行已批准批次

读取 coordination.md 中“最新主Agent—子Agent施工验收闭环”“当前总控规则”“批次闭环”“任务卡/交接格式”及当前总控记录。按原有规则完成以下流程，不用本摘要替代原文：

1. 核对工作区已有修改、用户批准的目标/范围、任务卡与所有权；已确认方案和 A/B 模式沿用，需评分时按原四维定义及证据裁定。
2. 核实指定施工与独立验收角色的实际配置/调用能力，按原分工派发。共享工作区交代文件所有权和禁止覆盖其他任务修改。
3. 施工者按任务卡施工、自查、必要测试及局部修复，交接后停写；主 Agent 按现行闭环组织独立验收，不凭施工者自述签收。
4. 独立验收读取实际差异、原标准和受测版本，遵原必要测试、预算及升级门禁；施工与验收角色保持分离，施工者不得自签。分别裁定本轮范围内缺陷与整个批次，记录实际命令、结果、提交或冻结指纹，未实测不得通过。
5. 按原流程更新既有 status/agent-control 与验收记录，汇报结果、证据、遗留问题、下一步计划及建议模式；遵现行“汇报后等待用户确认，不自动启动下一批”。同步仅按 AGENTS 的有效授权和当前用户限制执行，不因 Skill 自动获得权限。

指定 Agent 不可用、调用失败、主 Agent 配置不能满足现行指定，或工具无法保证指定模型/推理强度与独立分工时，明确报告失败/未验证证据及受阻步骤，停止依赖它的执行。不得静默换模型、由主 Agent 代工后冒称原闭环完成，或用提示词扮演代替实际配置。预检阶段只报告这些限制，不通过真实派发来验证。
