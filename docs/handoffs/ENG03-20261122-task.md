属于[工程整固路线图](../batches/ENG-HYGIENE-ROADMAP-20261122.md)第二批，依赖 ENG02 PASS。目标：

- 原始证据不再进入 Git，仓库体积停止增长；

- 用脚本和 CI 守住这两条，避免 ENG01 瘦身后 7 天回涨的情况重演。

## 评分与模式

需求明确度 0 / 模块耦合 1（涉及多份规则文档、CI 和少量测试夹具）/ 变更风险 1（迁移可能丢历史或断链，规则改动影响后续所有批次）/ 历史失败 1（ENG01 瘦身后 status 从 ≤20KB 回涨到 106.8KB）= **3，A 标准**。按 agent-router 当前规则选模型；验收者先审计划；施工与验收为不同实例。

## 必做

**V1 证据存放规范。** 新增 `docs/evidence-policy.md`（不超过 2 页）。

进入 Git 的：
- 施工、验收报告（Markdown）；
- 关键截图，每张 ≤300KB，每批 ≤10 张；
- 小型 JSON 或文本摘要，每个 ≤200KB；
- 证据清单文件。

不进入 Git 的：
- 完整日志、浏览器追踪、导出包、大型夹具、重复截图；
- 这些放仓库外 `<归档目录>/evidence/<批次>/`，提交 `docs/reports/<批次>-evidence-manifest.json`（相对路径、字节、SHA-256、用途），报告按清单引用。

可再生的大测试输入由测试运行时生成，不提交。另外在 `docs/coordination.md` 的“任务卡/交接格式”和 `docs/acceptance.md` 的证据要求处各加一句指向本规范，不改其他规则。

**V2 体积守护。** 新增 `scripts/repo-guard.ts`，加 npm 脚本 `guard`，接入 `npm run check` 和 `.github/workflows/ci.yml`。检查以下几项，超限即失败：

- 跟踪文件中单个大于 1MB；
- `docs/reports` 下非 Markdown 文件大于 300KB；
- `docs/status.md` 大于 24KB；
- `docs/agent-control.md`、`docs/acceptance.md` 大于 48KB。

存量超限文件写入 `scripts/repo-guard-allowlist.json` 豁免，每条附原因，名单只减不增；新增豁免须在报告中说明并经验收者认可。脚本需有单元测试，覆盖超限失败、豁免通过、名单外新增失败三种情况。

**V3 存量大文件迁出（不改写历史）。** 把 `docs/reports` 下 8 个大于 1MB 的文件移到归档目录：`git rm --cached` 后移动，写 manifest。修正引用这些文件的链接，指向 manifest 条目。不在本批迁移其他历史证据。报告列出：迁出后工作树体积、`docs/reports` 体积；说明 `.git` 历史不变的原因（D2）。

**V4 status.md 瘦身与写法规则。**

- `docs/status.md` 只保留：
  - “当前状态摘要”：当前阶段、最近 5 个批次各一句话结论、开放阻塞与待用户确认事项、下一步、路线图链接；
  - 最近 7 天的条目。

  总体积不超过 20KB。更早条目**原文**搬到 `docs/archive/status-2026-11b.md`，status 内保留归档索引。
