## 目标与界面方案

使用已读取的 frontend-design Skill 与 DESIGN.md：服务本机快消 AI PM 的知识查阅，沿紫白配色、系统中文字体、白表面和浅边线。主要视觉变化集中在“左侧提问、右侧阅读”，不增加装饰、远程字体或全局主题重做。

桌面问答面板内采用左窄右宽的网格，左栏约 280–340px、右栏占剩余宽度且 min-width:0；具体比例由实际可用宽度决定。左栏放问题输入、提问/重试、阶段与错误；右栏放答案、保存操作/预览和独立的引用依据区。首屏无答案时右栏显示简短可操作空态；长答案自然向下阅读，避免内嵌多重滚动。

```text
向知识库提问                                      收起问答
┌问题输入 / 提问──┬回答：对应问题、分段正文与短引用 [1]──┐
│阶段 / 错误      │保存全部 / 保存选段 / 已有草稿         │
│                ├引用依据：编号、类型、标题、版本/定位──┤
│                │实际读取范围（折叠） / 保存预览       │
└────────────────┴─────────────────────────────────────┘
```

正文保留来源事实/综合推断/建议/依据不足/分歧待核标签和原文内容。行内只显示稳定短编号（按 answer.citations 顺序映射，非可信度排序），不再插入长标题。相同 citation ID 在全文使用同一编号，引用区明确列对应编号与真实标题/类型/版本或 Raw 位置，可展示已有 quote 以便核对。编号关联来源详情；可用本地锚点/展开定位，引用详情保留原 openCitation API 的校验后打开 Wiki/Raw 行为。不要绕过校验直接拼链接。详情与正文通过标题、间距/分隔线与轻背景建立明显区分，不能只靠颜色。

保持 answerText/answerSelection 的文本序列与边界。引用仍置于 data-answer-citations 容器，以便跨段选择排除引用；避免可见标签被重复加入 selectedText。窄屏（建议 <=900px，依据实际侧栏可用宽度微调）依次为提问、回答、依据、预览，所有操作可达且无横向溢出。

## 冻结验收项

| ID | 必须满足及证据 |
|---|---|
| Q01 布局 | 实际浏览器 1440 或1536、1024、390px：宽屏左提问右阅读且右栏更宽，窄屏顺序正确，长标题/长正文无横向溢出；空态、回答态截图可审阅。 |
| Q02 内容与引用 | 多段且含事实/推断/分歧的合成答案：正文、类别标签不丢失；行内短编号和独立引用区一一对应，同一引用复用编号；依据标题和元信息不会混作回答正文。 |
| Q03 引用操作 | 至少真实 HTTP+本地 fake 的 Wiki 与 Raw 引用各一条：从回答编号能定位对应依据，从依据打开正确 Wiki / Raw 原文高亮；继续沿原 citation API，失效引用显示错误。键盘可到达编号、来源和主操作，焦点可见。 |
| Q04 选段与回存 | 实际浏览器跨段选择（经过短引用）后的 selectedText 不含引用编号/标题；保存全部与选段预览正确保留分类、sectionIds、citationIds。取消无草稿写入，明确生成才出现维护草稿，正式知识未改变；已有草稿入口仍可用。 |
| Q05 状态与回归 | 请求中禁用重复提问/保存且有阶段反馈；失败/依据不足不伪装新成功，旧答案保留时明确对应旧问题；失败重试仍显式触发。保存失败保留编辑预览。浏览器无新增页面异常，相关 LW02 定向测试和类型/隔离构建通过。 |
